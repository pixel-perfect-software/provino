`provino jest` writes inline snapshots as Jest 30.5.2 does: a new one, or one that differs under `-u`, goes into the test file once the file ends, the call reprinted with Babel's generator exactly as jest-snapshot does (Babel is loaded only when a snapshot is written, from the project's install first, then Provino's pinned copy), and the file formatted with the project's Prettier 3 when it has one (Prettier 2 writes unformatted, with a warning). Jest's errors are kept: one call reached twice fails its file, and a file that fails that way counts none of its tests. A project's `snapshotResolver` is applied, loaded through each test file's registry, with Jest's texts for a resolver that lacks a member or doesn't invert itself. After a run, the snapshot files no test file has are reported (and removed under `-u`) in the Snapshot Summary, as Jest's `cleanup` does, through a custom resolver's inverse too. `SnapshotPolicy` gains `inline.writer`, `inline.prettierPath`, `resolverFactory` and `obsoleteFiles`; `SnapshotFileReport` gains `inline` (`InlineSnapshotEdit[]`); `SnapshotMessages` gains the optional `noInlineFrame` (the dialect's own error for an inline snapshot whose call has no frame to write at; Jest's is its plain `Error`); `SnapshotRunSummary` gains `filesRemovedList`; `FileResult` gains `resultsDiscarded`; `SerializedProjectConfig` and `NeutralProject` gain `snapshotResolver`. New types: `InlineSnapshotEdit`, `InlineSnapshotWriter`, `InlineSnapshotWriterFactory`, `InlineSnapshotWriteOptions`, `SnapshotResolver`, `SnapshotResolverFactory`. `@provino/dialect-jest/inline-snapshots` exports `jestInlineSnapshotWriter`, and `@provino/dialect-jest/runtime` exports `jestSnapshotResolver`.
