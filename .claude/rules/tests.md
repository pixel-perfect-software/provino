# Test, type-test and fixture rules

- **Unit tests run on Provino itself**, next to the source as `*.test.ts`. Write `import { describe, it, expect, … } from 'provino'` (the native API: `test`, the hooks, `fn`, `spyOn`, `lazy` and the rest are there too); the shared config resolves workspace packages through `provino-source`, so a test needs no flag. `node:assert/strict` stays allowed in a test, but new tests use `expect`. An import of `provino` is allowed in test files only (the boundaries manifest's `testOnlyEntry`, rule `test-only-entry`). Jest and Vitest are never our own runner; they appear only as *subjects* in the harness and bench.
- **The runner is the pinned published rc, never the checkout (D191).** The root's `provino-runner` devDependency (`provino-runner: npm:provino@<rc>` in the `pnpm-workspace.yaml` catalog) is what every `test` script and `pnpm test:provino` run (`RUNNER_BIN` in `tooling/packaging/src/dogfood.ts`), and the configs import `defineConfig` from `provino-runner/config`. Every package with tests but `env-node` has a `provino.config.ts`. The shared config gives the workers `provino-source` through `execArgv`, so a package's `test` task waits for no build (D206; the reasons, and the two packages that still wait, are in `tooling/packaging/src/dogfood.ts` and `tooling/provino/base.ts`). To bump the pin, edit the catalog entry and run `pnpm install`. A fix to the runner needs a new rc first, and a suite can rely on it only after the pin moves. Never point the pin at the checkout. `env-node` stays on plain `node --test`: its one file owns the process listeners the worker also holds. The mechanism (the `test` script, `RUNNER_BIN`, the shards) is in `tooling/packaging/CLAUDE.md` → Dogfooding.
- **The bootstrap set and the canary stay on `node:test`** (`node:test` + `node:assert/strict`, as before). `tooling/provino/bootstrap.json` maps each such file to why (the mechanism, or the runner bug it hides, precise enough to act on), and `packages/provino/test/bootstrap/canary.test.ts` is always in it: a runner that reports green wrongly must not be able to hide its own failures. A file joins by getting an entry with its reason, then `pnpm migrate:node-test rewrite <pkg>` refreshes the package's script, so the entry can come out when the bug is fixed. `pnpm test:shard check` holds every file to exactly one runner, and a test proves none runs on neither; how the script runs both halves and how CI shards them is in `tooling/packaging/CLAUDE.md` → Dogfooding. On Node below 22.18, set `NODE_OPTIONS=--experimental-strip-types` (CI's 22.15 leg does) for the bootstrap files, `pnpm boundaries` and the other scripts Node runs as TypeScript.
- **Type tests** (`*.test-d.ts`) use `expect-type` and must pass on TypeScript 7.0.2 and 5.9.3. Every misuse case is a `@ts-expect-error` line. Where the research gives the expected error text, assert a substring of the message so the error can't be a different one.
- **Goldens are recorded, never hand-edited.** Ground-truth observations and message/snapshot goldens come from running real Jest 30.5 / Vitest 5.0 through the recorder (one fixture format, T12.1). To change a golden, re-record it and explain why in the commit. Two recorded oracles are not recorder fixtures, real Vitest's `parseCLI` answers (`record:cli`) and real Babel's output for the Jest hoist layouts (`record:hoist`): CI re-checks each against the real tool with its `--check`, in place of the T12.1 recorder.
- **Determinism is a requirement.** Recorders must produce byte-identical output twice in a row. Seed anything random, and normalise paths, timings and PIDs through the harness's normalisation rules.
- **Never make a failing check pass by editing the expectation.** If Provino and the golden disagree, either Provino is wrong or the divergence is deliberate. Deliberate divergences follow DECISIONS D7, and each is listed in `docs/plan/DIVERGENCES.md` with the fixture that shows it.
- **Keep fixtures small and named for the behaviour** (`hook-order-after-each-reverse`), not numbered.
- **A test file does no work when it is imported.** The dogfood completeness test imports every file with `-t` to list it (`tooling/packaging/src/dogfood.test.ts`), and a `describe` body runs then too, so an oracle, a child process, a corpus load or a temp-dir build at module scope or in a `describe` body runs on every listing, and a skipped file never cleans up after it. Start it from the first test that needs it, memoised when several share it (`oracleOutcomes()` in `packages/dialect-jest/src/node/cli.test.ts`), or from a `beforeAll`, which a listing never runs. The same test makes each listing's `TMPDIR` an empty directory and fails when a listing leaves anything in it.
- **Reading the repo's own file list to name tests** (`migratedDirs`, `bootstrapFiles`, a directory listing in a `describe` body) is allowed import-time work: it is cheap, makes nothing on disk, and the test names come from it.
- **Tests keep scratch files in the OS temp dir or a git-ignored `.work/` dir, never in a checked-in folder.** The boundaries scan walks the tree while other packages' tests run, so a file a test makes in a checked-in directory can be listed and then be gone when the scan reads it. `.work/` is git-ignored and in the scan's `SKIPPED_DIRS` (`tooling/boundaries/src/paths.ts`).
- **A file a test reaches makes no value import of the other runner's API.** A node:test `after`, `test` or `describe` does nothing in a Provino worker (a temp dir its `after` was to remove stays), so no file a Provino-run test reaches (the test file included) value-imports `node:test`. A helper that only Provino tests import uses `afterAll`/`onTestFinished` from `provino`; one that bootstrap (node:test) files import too takes the hook as a parameter or the test's `t`. The mirror holds too: no file a bootstrap test reaches value-imports `provino` (its `afterAll` registers nothing under node:test). A type import is erased and fine, and so is a file only the other runner's tests reach. `pnpm test:shard check` fails on either and prints the chain of imports. The one exemption is a helper that picks the runner at run time, today `packages/provino/test/support.ts` (`testRunner()` reads the `provino.api` slot a Provino worker installs and uses node:test only without it); the mechanism is in `tooling/packaging/CLAUDE.md` → Dogfooding.
- **Real-time waits are banned in unit tests.** Use fake clocks or explicit signals; flaky tests get fixed or deleted, never retried into green.
- **A slow or timing-out test gets faster, not a longer timeout.** Measure why it is slow (CI against local, and the test's duration under the old runner), then fix the mechanism with the same cases: batch child processes, reuse a loaded oracle, record oracle output as a version-keyed golden, scope a whole-repo check to a fixture when CI already runs the full one. Raising a timeout or loosening a threshold needs Tyler's OK and is a labelled, temporary stopgap at most.
