# @provino/transform

The per-file transform pipeline (Track 3): TypeScript and JSX through Oxc, mock hoisting, source-map composition, import records, and the module-runner rewrite. Follow `.claude/rules/typescript.md`.

## Layout

| Path | Role |
|---|---|
| `src/pipeline.ts` | `createPipeline().transform(request)`: route by extension, `oxc-transform.transformSync` with tsconfig-derived options, then `hoistMocks` for every role but `dependency` (B13b Gap 3), then the record's import facts. `hasTopLevelAwait` reads the original source only (`moduleFacts`): the hoist step's rewritten imports are `lateDeps`, not top-level await (D38). Hoister diagnostics are appended to the record's. The pipeline passes `source` as `original` (see "Generated names"). With `runnerForm: true` (the loader's) it also makes the module-runner form of an ES module as it stores the record ("The module-runner transform" below). `format` is `esm` for module syntax or `.mjs`/`.mts`, `cjs` for `.cjs` and for a file with no module syntax that calls `require` or reads a member of `module`/`exports` (`hasCommonJsSyntax`, from the AST, so a comment doesn't count), else `unknown`. |
| `src/module-runner.ts` | `toModuleRunner(filename, record)`: the module-runner form (`runner/`), from `record.runner` when the pipeline kept one (the cache's), else made now. Only ever sees stripped output; a parse or semantic error is a per-file `TRANSFORM_RUNNER_FAILED` naming the file, and unstripped TypeScript is a parse error. `map` is composed on first read. No production file names oxc's deprecated `moduleRunnerTransformSync` (a test enforces it; D10). |
| `src/runner/` | Our module-runner transform (T3.13, B20), below. |
| `src/internal/` | `maps.ts` (compose maps), `imports.ts` (import records), `position.ts` (offset to line and column; `positionCursor` for ascending offsets), `tsconfig.ts` |
| `src/hoist/` | The mock hoister (T3.4), below. |
| `src/jest-host/` | The Jest transformer host (T3.8), below. |
| `src/cache/` | The transform cache (T3.6), below. |

## The module-runner transform (`src/runner/`, T3.13)

`rewriteModule(filename, code) -> { code, edits, deps, dynamicDeps }` on `oxc-parser` (`parseSync`, raw transfer, `showSemanticErrors: true`, so `Export 'x' is not defined` and ``Identifier `x` has already been declared`` fail the file as they did under oxc's). The output has oxc's shape: every export a `Object.defineProperty(__vite_ssr_exports__, name, { get() { return local } })`, then every import as `const __vite_ssr_import_N__ = await __vite_ssr_import__("spec", { importedNames: […] })` (no `importedNames` for a namespace or side-effect import), all above the module's own statements and after a hashbang and directives; uses become `__vite_ssr_import_N__.name` (a callee `(0, ns.f)()`, a shorthand property `{ f: ns.f }`); `export default expr` is `const __vite_ssr_export_default__ = expr`; `export *` is `__vite_ssr_exportAll__(ns)`; `import()` and `import.meta` become `__vite_ssr_dynamic_import__` and `__vite_ssr_import_meta__`. The loader's wrapper parameters and its textual `await __vite_ssr_import__(` strip are the contract (D36/D38: imports still move above everything, so `reExports: 'static'` and the hoister's late imports are unchanged).

| File | Role |
|---|---|
| `analyse.ts` | One walk over the AST: the references to an import's local name, `import()` and `import.meta`. Scope analysis is purpose-built and deferred: each reference records its scope, each declaration of an import's name goes into its scope, and `isImportReference` decides afterwards. Scopes follow the language (a function's parameters and its body are two scopes; a `switch`'s cases share one the discriminant is outside). It does not share `HoistScopes` (B20 Gap 6 said to try): that class rides `oxc-walker`'s `ScopeTracker` and keeps three Babel-isms the runner must not have; a separate walk is what holds the speed bars. |
| `apply.ts` | The edits, as plain `{ start, end, text }` records applied by slicing (`RunnerEdit`, in `@provino/types`). `magic-string` is built from the same records only when a map is read (`mapOfEdits`, `hires: 'boundary'`), so the cost sits with the stack trace, not every warm run. `RUNNER_FORM_VERSION` is a fingerprint input: bump it when the form changes for the same input. |

**Bug-compatible with oxc on purpose** (B20 Gap 4; changing one is a decision): `a = 1`, `a++`, `[a] = x` and `({ a } = x)` on an import's name stay as written; a tagged template gets no `(0, …)` (`this` is the namespace); a parenthesised callee `(a)()` is a plain read; import attributes are dropped; a namespace import called as a function is `ns()`.
**Different from oxc, each listed in `bench/runner-exemptions.ts`:** `import d, * as n from 'x'` binds `d` to `.default` (oxc leaves `d` a free name, a ReferenceError); two `export default`s are an error even when the file name says TypeScript (oxc parsed the stripped code as TypeScript, where they read as overloads); a hashbang becomes `//`, the same length (the loader runs the code inside a function, where `#!` is a SyntaxError). Not exempt, deliberate: a `var` in a `catch` block that redeclares an import is the parser's "already declared" error, which oxc-parser lets through (the walk reports it); `deps` and `dynamicDeps` are in source order, once each (oxc's is a hash's order, so externals preloaded in a hash order); comments and formatting stay where they were; unstripped TypeScript is a parse error, never an abort.

**Checks.** `pnpm bench:runner-diff` compares our output with oracle A (oxc's `moduleRunnerTransformSync`, kept in `bench/` only) as ASTs (positions, raw text, comments and empty statements dropped) on the fuzz corpus (10,000 files, 9,813 of which strip), the excalidraw ESM files (680 of 687) and the scoping corpus (`bench/scoping-corpus.ts`: 294 hand-written cases in 18 groups and 5,000 seeded programs, unique, with about 5% redeclaring an import binding on purpose so the error path stays covered: 274 of 5,294 are error-only comparisons; the generator tracks each scope's names so the rest are valid), plus errors, `deps` as sets, `dynamicDeps` and export names, and both outputs must parse; a difference needs an exemption entry and an unused entry fails. It prints each corpus's requested, compared and error-only counts and fails a corpus that compares 0 files. Oracle B (`execute` in `bench/runner-oracle.ts`: the loader's wrapper parameters, a stub `__vite_ssr_import__` that logs and returns deterministic namespaces) runs every fuzz file both transforms made code for that no exemption covers (8,130, 0.62 s `local`, so none is left out) and compares logs, exports and errors. A pair where neither side compiles the wrapper, with the same SyntaxError (2,433: decorators and `accessor`, which this Node cannot compile), is `notRunnable`: nothing ran, so it is counted apart and is not `checked`; one side compiling and the other not is a difference. 5,697 are `checked` (3,268 with a non-empty log, `withLog`), and 0 `checked` fails the run. Files with `import d, * as n` are exempt, so oracle B does not run them. `--plant scope|order|member` plants a wrong scope rule (the first `(x) => x…` arrow reads `x` as an import), a swapped import order or a wrong member read, in our output, and the check must fail (exit 1): `scope` is seen by the AST comparison only (the fuzz corpus never calls that arrow), `order` and `member` by oracle B too (1,026 and 2,795 files differ). Speed (`--max-median-ms`, `--max-mean-ms`, `--max-route-median-ms`) times oracle A and ours interleaved on the 680 ESM files, `local`. Every bar is opt-in; a bar that is not a number above 0, a bar with `--skip-speed`, a plant with `--skip-diff`, an unknown plant or a size that is not a whole number of 1 or more exits 2 before any work. `bench/runner-equivalence.test.ts` runs the scoping corpus in `pnpm test`, with a program that shadows a mixed default import, run and asserted by its exports. CI runs `--skip-speed`.

**The cached runner form (B20 Q3).** `createPipeline({ runnerForm: true })` (the loader sets it) makes each ES module's form when it stores a record (a file the loader would run the step on: format `esm`, or `unknown` with an `import()`; none with an error diagnostic or a step failure), so `TransformRecord.runner` (`RunnerForm`: `code`, `deps`, `dynamicDeps`, `edits`) is cached and a warm hit makes `toModuleRunner` return it without parsing. It is a fingerprint input (`runnerForm`: `RUNNER_FORM_VERSION` or `null`), so plain and runner-form entries never share a key. `bench:transform-cache` prints the warm route (hit plus the step) three ways, interleaved with the order rotating by file and pass, `local`, and fails when a warm hit's runner form (`code`, `deps`, `dynamicDeps`, `edits`) differs from the one made fresh from the uncached record.

## The Jest transformer host (`src/jest-host/`, T3.8)

`createJestHost(config: SerializedTransformConfig) -> Promise<JestHost>`, built in the worker by `createProjectLoader` and handed to `createPipeline({ transformers })`. It does what `@jest/transform`'s `ScriptTransformer` does (jest-transform 30.5, read from `.refs/jest`): the first `rules` entry whose pattern matches the real path picks the transformer; `ignorePatterns` (joined with `|`) opt a file out (`handles`); `getCacheKey(Async)` and `process(Async)` are called with the same options (`supportsStaticESM`, `supportsDynamicImport`, `supportsExportNamespaceFrom` and `supportsTopLevelAwait` all `false`: jest-runtime's CommonJS path; `config` is the project config as JSON, `configString` its stable text; `getCacheKeyAsync ?? getCacheKey` and `processAsync ?? process` are called detached, as Jest does).

- **Loading:** each rule's module is imported by absolute path or `file:` URL from the worker, so it is the project's own install (its `node_modules`, its version); this package takes no dependency on any transformer. `default` of an ES module, else `module.exports` (and its `default` when `__esModule`); an ES module with only a named `createTransformer` works. `createTransformer(options)` runs once per rule and may be async. A module with neither `process` nor `processAsync` is `TRANSFORM_TRANSFORMER_INVALID`; one that can't load, or whose factory throws, is `TRANSFORM_TRANSFORMER_LOAD_FAILED`.
- **Sync and async:** `transform` needs `process`, and a transformer with only `processAsync` throws (Jest's `makeInvalidSyncTransformerError`). The loader reads files synchronously (`ModuleTransformer`), so only `process` is used today; `pipeline.transformAsync` takes `processAsync`. `@swc/jest`'s `processAsync` is always ESM ("async transform is always ESM"), which the sync form is not.
- **Output:** `{ code, map, transformerCacheKey }`; `map` is the transformer's (object or JSON text) else the one inlined at the end of its code. The record's `cacheKey` is `sha256(pipeline fingerprint, filename, role, transformerCacheKey ?? source)`; the fingerprint includes `host.fingerprint` (rules, options, ignore patterns, config). The cache (T3.6) asks `host.cacheKey(request)` (or `cacheKeyAsync`) first, looks the entry up under `sha256(fingerprint, filename, role, instrument, transformerKey ?? source)`, and passes the key it got to `host.transform(request, key)` so `getCacheKey` runs once per file.
- **Format and hoisting:** the output is CommonJS, so the format comes from its own syntax. `hostedRecord` runs our hoister on it unless it contains one of `hoistedMarkers` (Babel's Jest plugin writes `_getJestObj`): a transformer that hoisted leaves nothing to move, and ts-jest's and `@swc/jest`'s hoisted output (no marker) goes through the hoister, which finds each call already at the top and leaves one of each (it may move it past a prologue statement). Gap 1: D38's import rewrite applies only to our hoister's output, and CJS output has no static import to rewrite.
- **A transformer that throws** is a `TRANSFORMER_FAILED` error diagnostic on the record (the loader formats it as `transform-failed`).
- **Default transform:** the Jest dialect leaves Jest's default `babel-jest` entry (no options) out, so a project that names no transformer keeps the Oxc path (`to-neutral.ts`), unless the project has a Babel config (D68): then the entry stays and the real babel-jest runs (its `getCacheKey` covers the config, so an edit misses the cache; `provino/test/implicit-babel.test.ts`). A project that names `babel-jest` itself gets it.
- **Tests:** `host.test.ts` runs the real babel-jest 30.5.2, ts-jest 29.4.15 (TypeScript 5.9.3) and `@swc/jest` 0.2.39 on `fixtures/jest-host` (a TypeScript test with `jest.mock` below its imports, a factory reading a `mock`-prefixed variable and a `__mocks__` file; `jest.<tool>.config.json` for each); the end-to-end statuses against real Jest are `packages/provino/test/transformers.test.ts`. ts-jest finds its TypeScript from the working directory, so run it from the project.

## The transform cache (`src/cache/`, T3.6)

`createPipeline({ cache: { dir } })` reads an entry before any work and writes one after it; `cache: false` (`--no-cache`) does neither. Both paths go through it, the Oxc path and hosted transformers. **The directory** is the coordinator's choice: `<rootDir>/node_modules/.cache/provino/t` (`transformCacheDir` in the orchestrator, inside the results cache's directory, so `--clearCache` and a cold bench run, which delete that, delete this). When the Jest config sets `cacheDirectory` itself (D70), it is `<cacheDirectory>/provino/t` instead (CI setups cache that directory); Jest's own `/tmp/jest_*` default is never used, as for the results cache. The Jest dialect carries the value as `NeutralProject.cacheDirectory` only when it differs from Jest's default (`jestDefaultCacheDirectory`), so a config that names the default path itself stays on `node_modules/.cache/provino`.

| File | Role |
|---|---|
| `fingerprint.ts` | `pipelineFingerprint(inputs)` (R5): this package's version and a hash of its own code files (`code-identity.ts`: `src/` from source, else `dist/`; tests, `.d.ts` and `test-*` helpers left out; computed once per process, about 3 ms cold, `local`, so an edit to the hoister misses the cache although the version is `0.0.0`), `oxc-transform`'s and `oxc-parser`'s, the TypeScript mode, `process.version` **only under `node-strip`** (Oxc's output doesn't depend on Node), tsconfig mode, JSX and `define` options, the hoist policy (every field, `RegExp` and `Set` included, through `stableJson`) and the transformer host's fingerprint (its rules, options, ignore patterns, config). `hashParts` is `crypto.hash('sha256')` over NUL-separated parts. |
| `store.ts` | `createTransformCache(dir)`: `get(key)` and `set(key, record)`. One file per key at `<dir>/<2 hex>/<key>`: a one-line JSON header (`v` 2, `codeBytes`, `mapBytes`, `format`, `imports`, `staticMocks`, `lateDeps`, `hasTopLevelAwait`, `diagnostics`, `runner`), `\n`, the code, the map's JSON text, then, when the record has a runner form, its code and its edits' JSON (`runner` holds their lengths and the `deps`). `code`, the map and the runner form's code and edits are lazy getters on a hit: a warm run evaluates the runner form and reads none of the rest. The first `set` of a process also leaves a `.written` sentinel in the directory, which `pruneCacheIfWritten` removes (directory mtimes can't tell: a Linux write in the same clock tick leaves them unchanged). A write is a temp file plus a rename; a length that doesn't match, a bad header or another version is a miss. A record with an **error** diagnostic isn't stored (a parse error or a failed transformer is met again); warnings are stored and replayed. Everything is best effort, so a directory that can't be written is a cache that misses. `CACHEDIR.TAG` is written on the first write. |
| `maintenance.ts` | The coordinator's half: `lockfileHash(root)` (the nearest `pnpm-lock.yaml`, `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock` or `bun.lock*` at or above the root), `prepareCache(dir, hash)` (wipes the directory when its `lockfile-hash` stamp differs; a `null` hash leaves it alone), `pruneCache(dir, maxBytes = 512 MB)` (oldest entries by mtime first: a hit doesn't touch its entry, so it is least recently written, not read; also removes a temp file over an hour old). `@provino/config`'s `withTransformCache` and `pruneTransformCache` call them, so workers never wipe. |
| `test-entries.ts`, `hammer.ts` | The tests' deterministic entries, and the child process of the 8-writer test. |

**The key** (Oxc path) is `sha256(fingerprint, filename, <the oxc options and the tsconfig's missing extends, as text>, role, instrument flag, source)`; so a change to the tsconfig's `jsx` (through the options), the role, the file or its content misses. The options' text is memoized per config and route, because a warm run pays for it on every file. **Tests:** `store.test.ts` (round trip with `staticMocks` and `lateDeps`, torn entries, 8 child processes writing the same 500 keys with no torn read), `maintenance.test.ts` (`prepareCache` retries an interrupted wipe once and returns `false` if it still fails, so `withTransformCache` hands the workers no `cacheDir` and warns), `fingerprint.test.ts` (each input moves it, the Node version under `node-strip` only), `pipeline-cache.test.ts` (through the pipeline: hits restore everything, the jsx, hoist policy, a transformer's key and options each miss). **Bench:** `pnpm bench:transform-cache [--max-warm-ms n]` over the excalidraw corpus: a cold fill, then 15 passes each with a new pipeline; the median per file, `local`; every warm record must be a hit and equal the uncached one. A record's code is `local` ≈ 0.04 ms/file warm against 0.17 uncached, but the number moves with machine load: a loaded laptop shows 0.05 to 0.06 on some runs.

## The hoister (`src/hoist/`)

`hoistMocks(code, policy, { filename, original? }) -> { code, map, staticMocks, diagnostics, rewroteImports, lateDeps }`. One neutral engine driven entirely by a `HoistPolicy`; it never compares against a runner's name. Pure: it reads nothing but its arguments.

| File | Role |
|---|---|
| `index.ts` | `hoistMocks`: prefilter, parse, analyse, apply. Any error returns the input untouched, with the errors as diagnostics. A failure of the step itself, such as a `MagicStringError`, is `TRANSFORMER_FAILED`; it never throws. |
| `prefilter.ts` | A regex built from the policy's `hoistCalls`, `hoistValues` and `rewriteImportArg`, cached per policy: a name, then `(` with only whitespace and comments between, or any `\u` (an identifier can spell a name with an escape). No hit returns the input with `map: null`. A hit in a comment or string costs one parse and edits nothing. |
| `parse.ts` | `oxc-parser` `parseSync`, with `experimentalRawTransfer` when `rawTransferSupported()` (about 3x faster), `lang: 'jsx'`, `sourceType: 'unambiguous'` (CommonJS files work), `preserveParens: false`. A syntax error is `PARSE_ERROR`. |
| `analyse.ts` | Finds what to hoist and checks the policy's rules; edits nothing. Two walks share one `HoistScopes`: the first only declares, so a `jest` imported below the call still resolves; the second, frozen, resolves each name from inside the walk. Recognition goes through `policy.objects`. It also picks the imports to rewrite (`Analysis.rewritable`: all but the runner's and type-only ones). Whether a binding is reassigned is by binding, not by name: a first pass collects the names written (destructuring and for-in/of heads included), and only a factory reading one of those names pays for the walk that resolves each write. |
| `scope.ts` | `HoistScopes`, an `oxc-walker` `ScopeTracker` with the two scopes it merges kept apart: a `var` belongs to the function's body, not the scope of its parameters, and a `switch`'s scope opens at its first case, after the discriminant. So references, the factory check, purity and reassignment get the language's answer. Three places follow Babel's bindings instead, because the Jest plugin reads them: `isDeclaredInMergedScope` is `hasBinding`, which sees a function's body from its parameter defaults and a `switch`'s cases from its discriminant, so the global mock object is shadowed there; a `var` of a parameter's name, or of a function expression's own name, declares nothing, since Babel holds one binding; and `isRedeclared` makes a second `var` of a name count as a write. It relies on protected members of the pinned 1.1.1, and the hoist corpus catches a break. `getUndeclaredIdentifiersInFunction` stays on the base tracker: Babel has the same merge there, so `(a = k) => { var k }` agrees. Known difference, left because it needs a mock call inside a `switch` discriminant: `getBinding` is merged there too, so an imported `jest` or an allow-listed global shadowed by a case's `let` is still read as the outer one. |
| `purity.ts` | Babel's `scope.isPure(node, true)`, for `hoistPureConsts`. |
| `apply.ts` | The edits, with `magic-string`: `move` for hoisted statements (so positions survive in the map), `overwrite`/`update` for rewritten references. |
| `diagnostics.ts` | Code frames, and `{call}`/`{name}` filling from `policy.messages`. Positions come from `internal/position.ts`, shared with the pipeline. |
| `test-policies.ts`, `test-helpers.ts` | Small inline policies and helpers for the tests. They are not the dialects' values. |

Tests: `rules-block.test.ts` (enclosing-block rules, one rule per case), `rules-top-level.test.ts` (top-level-only rules), `rules-generated.test.ts`, `imports.test.ts` (the import rewrite), `order.test.ts` (the order layouts by name, TSX through the pipeline, and a seeded property test), `asi.test.ts` (what a move leaves behind in raw JavaScript), `live-exports.test.ts` (exports of imports, run in module-runner form), `review-regressions.test.ts`, `maps.test.ts` (28 probes traced with `@jridgewell/trace-mapping` to exact line and column). The agreement with the real Jest and Vitest hoisters is `packages/harness/src/hoist-corpus.test.ts`; the cost bar is `pnpm bench:hoist`.

### Two placements

- **`enclosing-block`** (the shape of Jest's plugin): a chain of calls on a mock object that is an expression statement, and whose calls all satisfy their argument rule, moves to the top of its own block. Hoisted pure `const`s (`hoistPureConsts`) go first, then calls, each in source order. A call whose arguments fail its rule, or a chain with one non-hoisting call, stays put and is not an error. As Babel's `getStatementParent` does, what moves is the nearest statement in a list: `if (c) jest.mock('./a')` and `l: jest.mock('./a')` move whole (and aren't in `staticMocks`, since whether they run is only known when they do), and a statement in a `switch` case stays. A namespace member can be computed: `G['jest']`.
- **`top-level-only`** (the shape of Vitest's): a call anywhere is a candidate; its statement must be directly in the program (or in an `if (<topLevelGuards>) {}` block, which hoists wrapped in the guard). Otherwise `HOIST_NOT_TOP_LEVEL`; a hoisted call inside another is `HOIST_NESTED`, reported first, as upstream throws it first, with `{call}` and `{name}` as the inner and outer calls and their arguments; exporting a result is `HOIST_EXPORTED`, in the `HOIST_EXPORTED_VALUE` text when it is one of `hoistValues`. `vi?.mock()` and `vi.mock?.()` are not candidates, as in both real hoisters.

### The import rewrite (D36, in D38's form)

The module-runner transform moves every import above everything, so a mock call below an import would never apply. Under both policies, when a call moves to the top of a file that has static imports, the output is: runner-module imports (`policy.runnerModules`, kept static), the hoisted block, `const __provino_import_N__ = await __provino_import__('./a')` in source order (D38: `LATE_IMPORT`, exported; the record lists those specifiers as `lateDeps`, and the loader supplies the function and strips the `await` when it evaluates synchronously, so a rewritten file has no top-level await of its own), then the rest, with every use rewritten through scope analysis (`.x`, `.default`, the namespace itself, `{ x }` becomes `{ x: ….x }`; shadowed names stay). `policy.rewrittenCalls` decides `this` for a call or tag through a named or default binding: `detached` writes `(0, ns.f)()` (with a leading `;` when it opens a statement in a statement list, since it starts with `(`), `member` writes `ns.f()`. `export * as ns` exports the namespace.
- **Exports of imports are live.** `export { x }` of an import, and `export { a } from` under `in-order`, become a getter on `__vite_ssr_exports__` straight before that declaration's late import, so a read during a cycle meets the namespace `const` in its dead zone rather than a frozen `undefined`. The export list keeps only its local names (`export {};` when none are left). Real Vitest's `hoistMocks.ts` leaves `export { x }` as written with `x` gone, so it exports `undefined`; this is a deliberate fix (D7), and `mod-reexport-live` records the real value.

- **`policy.reExports` says what happens to `export … from`.** `'in-order'` (Jest: Babel's CJS step keeps source order) loads each with the imports, after the hoisted block. `'static'` (Vitest: `hoistMocks.ts` rewrites only `ImportDeclaration`) leaves every one as written, including `export *` and named re-exports, so the module-runner transform moves them above the mocks and a re-exported module loads before mocks exist. `re-exports.test.ts` covers both, and that each output survives `toModuleRunner`.
- **Under `in-order`, `export * from` has no dynamic form in ESM.** It becomes a late import plus `__vite_ssr_exportAll__(ns)`, the module-runner helper the loader's wrapper passes in. So the hoister's output is only valid as input to `toModuleRunner` when a file has a program-level hoist and either `export *` or an export of an import: the getters use `__vite_ssr_exports__`, which the same wrapper passes in.
- A block-level hoist leaves imports alone; a file with no static imports has nothing to rewrite (`rewroteImports: false`). A call named in `policy.rewriteImportArg` on a mock object also rewrites imports with nothing hoisted, as Vitest's `hasMockApiCall` does, so a file whose only mock call is `vi.doMock` has late imports.
- **How `arrange` in `apply.ts` orders moves.** `move(start, end, index)` inserts before the chunk that starts at `index`, wherever that chunk is by now, and throws only for an `index` within `[start, end]`. Queued statements consecutive in the target order and touching in the source merge into one block, so no index falls inside a moved range. The pivot is the first statement that stays; with none, the last block stays. Walking the blocks from last to first with `target` at the pivot, a block that ends exactly at `target` needs no move, every other block moves to `target`, and `target` becomes that block's start.
- **A move leaves `;` where the code needs it, by three rules.** Moved text ends in `;`: a statement moves as its node, so a `;` on a later line (`foo()\n;[1].map(f)`) goes with it, and one is added if it has none. Seam guards: when a moved block is followed by a token that could continue the line before (`[`, `(`, a backtick, `+`, `-`, `/`, `<`), it leaves a `;` at the old position, and a moved block that opens with one of those gets a `;` of its own. The detached opener: `(0, ns.f)()` opening a statement gets a leading `;`. TypeScript and TSX come out of Oxc with semicolons, so this is about raw JavaScript.

### Generated names

Hoisting runs after the JSX and TypeScript step, so a factory can read names the transform made (`_jsxDEV`). `options.original` is the source before the transform: a free identifier in a factory that does not occur in it, as a whole identifier, was generated and is allowed, under any policy. Without `original` nothing extra is allowed.

### Contract choices

- Calls keep their text. Nothing is rewritten to `__provino_mock__.register` (B13b Gap 1).
- `staticMocks` lists hoisted calls with a literal, template, or `import()` specifier, in source order. `automock` is "exactly one argument". `factoryLoadsOriginal` is a factory with parameters, or whose text names `importActual`/`importOriginal`/`requireActual`/`requireOriginal`. `loc` and diagnostic positions are in the hoister's input (the stripped code), not the original TypeScript.
- A hoisted `const` in a multi-declarator declaration is allowed by the factory rule but not moved. `export const` moves whole, with its export.
- Code frames are two lines of context either side of the position, with a caret; the text is the policy's.
