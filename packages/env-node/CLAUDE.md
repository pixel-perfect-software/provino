# @provino/env-node

The Node test environment (Track 8, T8.2's node part and T8.3). Runs in the worker; imports `@provino/types` only. `nodeEnvironment` (realm `worker`, no `prepare`) does not build a global: test code sees the worker's own `globalThis`, and `teardown` puts it back. Realm `context` needs the `realm` isolation tier (T2.8); `setup` throws `ENV_NODE_REALM_UNSUPPORTED` for it. jsdom and happy-dom are B17.

## Map

| Path | Role |
|---|---|
| `src/environment.ts` | `nodeEnvironment`: `setup` snapshots `globalThis`, `teardown` restores it |
| `@provino/env-shared`'s `src/restore.ts` | `snapshotProperties(target)` (moved there by D71, shared with the Jest adapter): `restore()` returns the keys it could not restore. Generic over any object, so tests plant a non-configurable property on a plain object instead of on the real global (it can never be removed again). The rules below describe it |
| `src/errors.ts` | `NodeEnvironmentError` (`code`: only `ENV_NODE_REALM_UNSUPPORTED`) |

## A file's own `process` (`orchestrator.processObject`)

With `processObject: 'per-file'` in the setup context (the policy's `orchestrator.processObject`: Jest and neutral `per-file`, Vitest `shared`; absent means `shared`), `setup` assigns `globalThis.process = createFileProcess()` (`@provino/env-shared`) **after** the snapshot, so the assignment goes through the wrapped setter and `teardown` puts the worker's `process` back. The copy has listeners and an `env` of its own (see env-shared's CLAUDE.md), so a file's `process.on('exit')` never piles up on the worker's `process` (Node's `MaxListenersExceededWarning` after 10) and never runs at the worker's exit, as in Jest. Scope `worker` (isolation `none`) gets one copy for the worker. Provino's own worker code that must reach the worker's `process` (the runtime's `uncaughtException` listener, the jsdom bridge) imports it from `node:process` or takes it at boot, never from the global during a file. Measured `local` (Node 24.22, M-series): setup plus teardown about 185 µs per file against 75 µs with `shared`; the copy of `env` (reading the real `process.env` is slow) is most of it.

## The restore rules

- **What is captured:** every own key (`Reflect.ownKeys`, symbols too) with its descriptor. **What is compared at teardown:** `value` by `Object.is`, `get` and `set` by identity, and `writable`, `enumerable`, `configurable`, always against the original descriptors, never the setter wrappers below. Keys added since are deleted; changed or deleted keys are redefined from the original descriptor. Capture never calls an accessor.
- **Closure-backed accessors.** Node defines `process`, `Buffer` and `performance` (Node 26 also `localStorage`, `sessionStorage`) as get/set accessors whose value lives in a closure, so `globalThis.process = fake` leaves the descriptor identical. `setup` wraps the `set` of each configurable accessor that has both sides. The wrapper's first call reads the getter (the old value), then calls the original setter; the getter is never read unless a test assigned (Node 26's `localStorage` getter warns). `teardown` calls the original setter with the old value for each wrapper that ran, whether or not the key was redefined or deleted since, then puts the original descriptor back for every wrapped key, so no wrapper outlives the file. A getter that throws on that first read, or a setter that throws on the replay, makes the key a leak.
- **Setup reads every descriptor first, and keeps reading until a pass finds no new key.** V8 backs some Node globals (`Headers`, `fetch` and the other undici ones) with lazy data properties: the first descriptor read, not only the first value read, loads their module, and undici defines two non-configurable symbols on the global (`undici.globalDispatcher.1` and `.2`). Without this, the first file that touched `fetch` would add keys the teardown could not delete. `Object.getOwnPropertyDescriptors(globalThis)` triggers the same load. First capture in a process: 21 ms on Node 24.22 (`local`); later ones about 0.05 ms.
- **Lazy accessors** (Node's `defineLazyProperties`, which on some versions replace themselves with a value property on first read) are restored to the original getter. Harmless: it replaces itself again on its next read.
- **Key order is not part of the contract.** A deleted key comes back after every key that was never deleted, so it moves to the end of its group (string keys, then symbols). Restoring the order would mean deleting and re-adding every key after the first gap, which `NaN`, `undefined` and `Infinity` (non-configurable) forbid. If nothing was deleted the order is unchanged. `environment.test.ts` asserts the set, every key's descriptor, and the order of the keys that were never deleted.
- **A key that cannot be restored** (an added property that is not configurable, a changed one that can no longer take its original descriptor, an accessor above that cannot be reset) is a warning, not a failure (decision D22). Everything else is restored, then `teardown` returns an `EnvironmentTeardownReport` (`@provino/types`): `{ leakedGlobals }`, each key as `String(key)`. A clean teardown returns nothing. D22 has the worker warn and carry the list on `fileDone`, so the pool recycles the worker (B11). The next `setup` in that worker has the stuck key in its baseline, so it is reported once. A key Node itself adds mid-file that is non-configurable would surface the same way; the undici symbols are the only one found, and setup covers them.

## Tests

- `src/environment.test.ts`: the T8.2 done-when on the real global. Each case runs synchronously inside `guarded`, which puts the touched keys back from descriptors the test saved itself, and the checks run before it does, so a restore that does nothing fails them. Cases: new string and symbol keys, an overwritten and a deleted builtin, a getter over a value and the reverse, `Reflect.set` over `process`, `Buffer` and `performance` (`guardedValues` assigns the old values back in a `finally`, since a descriptor cannot undo a closure), a counting closure accessor (the getter is read once, and never on a no-op), `enumerable` and `writable` flipped, a self-replacing lazy global, all of it at once. Never set `configurable: false` on a real global here: it cannot be undone. The D22 case runs in a child process for that reason.
- `@provino/env-shared`'s `src/restore.test.ts`: plain-object cases, including the unrestorable keys (returned, not thrown) and the setter wrappers (throwing getter, throwing setter, second restore).
- `src/environment.test.ts` also holds `processObject`: twelve `per-file` files that each add an `exit` listener (one each, none on the worker's `process`, no `MaxListenersExceededWarning`), an `env` change that stays in its file, and `shared`/absent leaving the worker's `process` in place. End to end against Jest 30.5.2: `provino`'s `test/jest-process.test.ts` (the harness's `env/process-*` goldens).
- `test/env-node.test-d.ts`: the public types.
