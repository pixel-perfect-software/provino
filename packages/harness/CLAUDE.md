# @provino/harness

Dev-only (private). Turns Jest and Vitest output into the neutral result model, diffs two runs, and records the **golden fixtures** every later bundle reuses for ground truth: policy values (T1.7), mocking probes (T4.1), runtime traces (T5.2) and matcher-message goldens (T7.1). Spec: Track 12 (F1/F2, R1/R2, Harness API, site contract). Result types are in `@provino/types` (`result.ts`, `bench.ts`); this package holds the runtime.

## Policy ground truth (T1.7, B14a)

`fixtures/policy/` holds about 30 fixtures recorded from both runners for T1.7. Most name the key they show: an `observe` id is the leaf's path (`core.nameSeparator`) and the value is computed in the test from what the runner did. Others are read by a claim: a test's status or error (`core-outcomes`, `core-focus`, `core-timeouts`), or a black-box run's `observed` (`snapshot-*`, `orchestrator-*`, `report-default`). `defaults` calls jest-config's `readConfig` and vitest/config's `configDefaults` inside the run (D27). `core-globals-at-setup` traces which globals exist in a setupFiles module, a setupFilesAfterEnv module and the test file (`core.globalsBeforeSetupFiles`, `globals.names`). B14c added `orchestrator-match-path` (`orchestrator.globMatchesOn`: the same relative glob in Jest's `testMatch` and Vitest's `include`) and the `cli/` fixtures (`orchestrator.exitCodes.usage`: `cli/unknown-flag` under both runners, `cli/bad-config` under Jest; also `cli/pass`, `cli/pass-with-no-tests` and the Jest-only `cli/jest-test-path-pattern`, which `provino`'s `jest-exit-codes.test.ts` and `dialect-jest`'s `cli.test.ts` read). B21b (T9.15) added the `cli/global-setup-*` runs, all Jest-only black-box runs: `-order` (setup, test and teardown order, with `.ts` hooks), `-globals` (the teardown sees a `globalThis` key the setup set, a worker's test does not), `-throws` (no file runs; `Error: Jest: Got error running globalSetup - <path>, reason: <message>`, exit 1) and `-projects` (two projects; the recorder reserves `projects`, so they come from `--projects p1 p2`, in plain JavaScript because a project's own config has no TypeScript transformer, with a placeholder root test the format needs). They back `orchestrator.globalSetup.teardownOrder` (Jest's teardown runs in the setups' order) and `.failure` (the header the CLI prints: see below); Vitest's two are pending (T11.16). `provino`'s `global-setup.test.ts` reads all four. The review of B21b added nine more, all Jest-only black-box runs: `-root-projects` (a root-level hook runs after the projects', with the first project's `projectConfig`) and `-sequence` (three projects, listed a, b, c, whose test files are the largest in c: the setup order follows Jest's sequenced list, not the config's, and a path two projects share runs once with the first sequenced project's config; each project's `cacheDirectory` is inside its own root so no history reorders the files), `-throws-typeerror` (the header keeps the class, `TypeError`, and a multi-line message is the message, not frames), `-throws-object` and `-throws-string` (a thrown non-Error is `prettyFormat(value, { maxDepth: 3 })`; with `-throws` and `-throws-typeerror` they back `orchestrator.globalSetup.failure`: its claim calls the ref it is given, from `@provino/dialect-jest/global-setup` or `@provino/policy/behaviours`, on what each fixture's setup throws and holds `<class>: <message>` of the error returned to the golden's stderr, and the neutral behaviour is its `REF_FLIPS` flip), `global-teardown-output` and `global-teardown-throws` (the reporters' summary is dispatched inside `scheduleTests`, so a teardown's output and its failure come after the totals; the exit code is 1 for a throwing teardown after a passing run), and `-test-path-patterns` and `-no-test-path-patterns` (`globalConfig.testPathPatterns` is a `TestPathPatterns` object with an executor; `provino`'s `global-setup.test.ts` holds the reader's object to them). Their `keepLines` keep every stderr line that is not a stack frame (`^(?!\\s*at ).+`), so the golden holds the header and the message, not machine paths. `fixtures/discovery/` holds the `--listTests` sets (`default-globs`, `test-regex`, `roots`, `ignore-patterns`, `extensions`, `glob-negation`, `path-patterns`, `by-path`) that `provino`'s `list-tests.test.ts` compares with.

`src/policy-truth/policy-truth.test.ts` takes every leaf of both dialects' resolved policies, their hoisting rules (`hoist.*`) and their globals' names (`globals.names`), finds its claim in `claims/<slice>.ts` (the leaf's own path, or the nearest group above it), and checks each piece of evidence:

- `golden(fixture, { case?, read?, matches? })`: the value in the golden must equal the dialect's (`read` takes it from tests or `observed`; `matches(golden, value)` is for a message template the golden shows filled in), and must differ from every flip.
- `corpus('runtime' | 'mock' | 'mod' | 'expect', ...fixtures)`: the fixture runs through Provino's engine under the dialect's policy and under each flip (`corpora.ts`, with the corpus check's own comparison and allowances: the runtime corpus's pinned collection error codes, `MOCK_DECLARED` and `MOD_DECLARED`). Under the dialect's own value the corpus check must pass (`[]`), or a wrong value could pass by failing less; a flip is rejected when it makes the check fail. Every baseline runs once, before any flip. Errors that escape a run (`captureStrayErrors`, installed for the whole file) are never evidence, and any during the baselines fails the test. `corpus('hoist')`: `hoist-corpus/flips.ts` (`FLIPS`, which `hoist-corpus.test.ts` runs against the real hoisters) must hold a flip that changes this very leaf.
- `own(test, mentions, value, reason)`: Provino's key; `value` must be the dialect's value at the claim's path, and the test file (one that asserts it) must exist and mention the key. `inert(under, when, reason, readers)`: nothing reads the value while every leaf at or under `under`, each backed, has `when` (or `when(values)` holds), and D46's check: flipping the value must leave every `readers` fixture passing, so a new reader fails. `pending(owner, reason)`: not checked; the list is pinned in `EXPECTED_PENDING`, so it only changes on purpose.

A leaf may have several pieces; every flip (`flip.ts`: every other value of an enumerated key in `DOMAINS`, else one value of the same type, a string flipped at both ends) must be rejected by one of them. A leaf with no flip (a Set, a RegExp, a ref) needs `own`, a `golden` with `matches`, a hoist flip or a one-value domain; a behaviour ref a corpus can hold to its goldens has a flip to the neutral behaviour in `flip.ts` `REF_FLIPS` (today `core.formatEachTitle`, backed by the runtime corpus's `each-*` fixtures). The test also fails on a leaf with no claim, a claim that covers no leaf, an enumerated value outside its domain, a policy fixture's observation for a leaf that disagrees with the dialect, and the word `unverified` in any case anywhere in `packages/*/src` (line, block and JSDoc comments alike; the scan's own pattern and title are exempt). `the checks catch a wrong value` shows each check catching the hole the pre-merge review found in it. **To add a value:** add the key and the dialects' values, a fixture (or a corpus case) that shows it, and its claim; record the fixture.

## Recorder contract

`recordFixture(dir, profile, { check?, keepWorkDir? })` copies the fixture to a fresh directory under `.record/` (inside the package, so `node_modules` resolution finds the runners), writes the runner config and the trace setup, and runs the pinned Jest 30.5.2 / Vitest 5.0.5 with `CI=1`, `TZ=UTC`, `NO_COLOR=1`, `LANG=LC_ALL=C.UTF-8` (`LANGUAGE` and other `LC_*` removed) and the fixture's `env`. It converts the JSON, normalizes with that directory as `<root>`, and writes the golden: a `NormalizedRun` without `startedAt`, `env`, every duration and every `raw` (the runner's text holds machine paths), plus `profile` and `trace` where they apply. Keys are in a fixed order; 2-space JSON and a trailing newline. The work directory is deleted afterwards (`--keep` leaves it, check mode included); a failed cleanup never replaces the original error. A signal ends the CLI through `process.exit`, which skips that cleanup, so `internal/work-dirs.ts` keeps the live work directories in a set and removes them in an `exit` listener (not with `--keep`).

- **A failing test inside a fixture is expected; a broken run is not.** `HARNESS_RUN_INCOMPLETE` unless the result files equal the fixture's test files for that runner exactly, no file is `crashed`, no file has zero tests, and `runErrors` is empty. The message says which, with a crash's `fileError`. With `expectCrash` for the profile the rule inverts: every result file must be `crashed`, else `HARNESS_EXPECTED_CRASH_MISSING`, and each crash's `fileError.message` must contain the named text (a crash with no `fileError` fails too), else `HARNESS_EXPECTED_CRASH_MISMATCH`; a missing file and `runErrors` still fail. A missing or unparsable JSON file is `HARNESS_RUNNER_FAILED`.
- **Trace.** Read after the completeness check; non-empty with more than one test file for the profile is `HARNESS_TRACE_MULTIPLE_FILES`. It is part of the golden text, so `--check` compares it.
- **Checkout guard.** A Jest profile is refused (`HARNESS_CHECKOUT_HIDES_JEST_FRAMES`) when the checkout's real path makes Jest take its `node_modules/` frames for Jest's own (jest-message-util's `JEST_INTERNALS_IGNORE`: a directory whose name contains `jest`, directly followed by `node_modules/` or `build/`). A worktree named `b23a-jest-results` hid the `expect` package's frames that CI prints, and `--check` there agreed with the wrong golden. Record from a worktree such as `agent-*`, or a checkout path without one.
- **Leak guard.** `HARNESS_GOLDEN_LEAKS_PATH` if the serialized golden contains the work dir (or its realpath), the repo root, the package dir or the home dir. Fix the normalization rule, never the golden.
- **Timeout** (2 minutes, `TIMEOUT_MS` in `record.ts`) is the harness's own deadline: the runner is spawned with `spawnInGroup`, so on timeout the whole process group gets SIGTERM, then SIGKILL after 2 s, and the run settles 0.5 s after the child exits even if a grandchild holds the pipes. The CLI calls `exitOnSignals()`, so Ctrl-C, SIGTERM and SIGHUP end it with exit code 128 + the signal number, and the exit hook in `spawnInGroup` kills the group on the way out (it is registered first among the `exit` listeners, so the work directory is removed after the group is gone). A grandchild that starts its own session is out of reach.
- **`--check` also fails on stale goldens:** any `__goldens__/*.json` this run did not produce (runner removed from `fixture.json`, no manifest, stray file). With directories given, only those are scanned.

**To add a fixture:** make the directory, write `fixture.json` and the tests, run `pnpm provino-harness record packages/harness/fixtures/<area>/<behaviour>` from the repo root (a directory of fixtures such as `fixtures/runtime` works too; no argument records all), read the golden, and commit it. To change a golden, re-record it and say why in the commit. CI runs `provino-harness record --check`, which exits 1 on drift.

## The self-test sample (T12.6) and the parity commands

- **`sample/`** is one fixture in the fixture format (`fixture.json` with `jestEsm`), outside `fixtures/`, so `record` never reads it (its completeness rule refuses one crash among passing files). It is the spike's 63-test sample rebuilt in TypeScript from Track 12 Spikes A: 18 file keys, 88 tests, every listed feature, the F3 divergences, and `normalization-inputs.test.ts`, which throws and prints the text the rules exist for. `crash.test.ts` must crash, and nothing else may (`internal/sample.ts` `sampleRunProblems`).
- **A per-dialect pair is one file key.** `modules.jest.test.ts` and `modules.vitest.test.ts` are copied as `modules.test.ts` into their runner's copy (`sampleCopy`), so both runs report one file. `exclusions.json` and `__recorded__/` are never copied.
- **`self-test`** runs Jest (`--ci -u`) and Vitest (`run -u --allowOnly`) each in a fresh copy under `.record/` with `runner-config.ts`'s configs and `CI=1`: `-u` against an empty snapshot directory is R2's snapshot set, and Vitest refuses `.only` under CI otherwise. Then it checks, one line each: every file ran, the golden of the fresh run equals the golden of `__recorded__/<runner>.normalized.json`, the sidecar wrote `console.test.ts`'s lines (Jest per file in call order; Vitest per test, each stream in order), and the calibrated diff (matcher mode, console on, the 4 rules, `--max-diffs 0`): all three parities 1, `suitePass`, each rule matched a diff, ≥63 tests, ≥16 files, exactly the one crash. CI's `suites` job runs `self-test --candidate provino`. `--candidate provino` runs the `provino` bin on the Jest copy (`provino.config.ts`, `--no-cache`), passes when it exits 0 or 1 with a valid `normalized-json` **and its status parity against Jest is at least `PROVINO_STATUS_PARITY_FLOOR`** (T12.16's bar, B17d, D30: 84 of the sample's 88 reference tests, the share measured when it was set; raise it when parity improves, never lower it to pass), and writes the exact-mode `ParityReport` to `--out`. It prints no Provino number (public CI logs); a miss says only that parity is below the bar.
- **The 4 calibration rules** (`sample/exclusions.json`, D30: no `expires`, read only with `--calibration`) are the spike's three (`div/beforeAll-failure-status`, `div/mockReset-restores-impl`, `div/snapshot-file-format`) and `div/runner-made-error-frame`, which Tyler added at B15. Jest gives an error it makes itself (a thrown string, a `test.failing` that passed) the stack captured where the test was defined, so it has a user frame; Vitest has none. That rule is `kinds: ['user-frame']` with `absentIn: 'candidate'` (it matches only a diff where Vitest has no frame), no key glob, and no policy key yet. B15's first calibrated diff had a third unexplained frame, `toThrow`'s, which was a parse of Jest's message layout and is fixed in `internal/stack.ts` (see Gotchas → Stack and frame rules).
- **`__recorded__/`** is written only by `self-test --write-recorded`: each runner's JSON (pretty-printed) and sidecar with the work directory, the repository and the home directory rewritten to `/__root__`, `/__repo__` and `/__home__` (`rewritePaths`, only where a directory ends: a separator, a quote or the end of the text), checked by `assertNoPathLeak`, and their conversion with `/__root__` as the root and a neutral `env` (`recordedEnv`: the runner's version and the Node major; every machine field `unrecorded` or 0, because the repository is public). `convert-recorded.test.ts` converts the committed raw files and must get the committed run; `normalize.fixtures.test.ts` takes T12.2's cases from them. Biome skips the directory.
- **`diff`** reads two `NormalizedRun` files (`parseNormalizedRun`), so a golden can't be diffed: it has no `env`, `startedAt` or `raw`. `--min` is status parity (R2's gate metric), which can't see a message or console diff: `--max-diffs` is the bar for those. `--max-excluded` counts every reference test left out of T, by a rule or as flaky (`counts.excluded`, D65), over the reference's tests, so a flaky list can't hide differences; the sample's are 3 of 88, over 2%, which `--calibration` allows (D30). A rule can match by kind, key glob, runner pair and `absentIn` (`reference` or `candidate`: only a diff where that run has nothing).
- **`diffRuns` for a `provino:*` candidate** treats a matcher name (matcher mode) or a passing-assertion count that the reference has and the candidate lacks as a diff (B02's deferral); Vitest's JSON has neither, so for it a missing field can't disagree. Flaky keys (`DiffOptions.flaky`) leave T and report nothing.

## The corpus (T12.9, T12.10, B16)

`./corpus` (`src/corpus/`, `commands/corpus.ts`) pins, fetches, installs and runs the 33 repos of Track 12 F5. `corpus/manifest.json` (committed; Biome skips the directory) is the data: per repo the full SHA, tarball sha256, MIT, package manager and lockfile (named as data only, D40), `testScript`, `skipped` projects and **subjects** (`manifest.ts`: one direct runner invocation in one directory, with `argv`, `env`, `prepare` steps and `provinoRefuses` for flags `provino jest` refuses). `r6` marks the five R6 repos, one subject each (styled-components on main, D41). A repo that tests through nx, turbo or lerna has one subject per package its script covers, with no cap (D56): 136 subjects over the 33 repos (nx 41 Vitest and 9 Jest, TanStack/query 26, typescript-eslint 14; TanStack's vue-query is the Vue 3 run of the script's three, selected by a `vue-demi-switch 3` prepare step). `corpus/<subject>/exclusions.json` and `flaky.json` are the committed per-subject files.

- **Pin and fetch.** `pin.ts` resolves F5's `f5Sha` through `gh api` and fills or checks `sha`, `commitDate`, `tarballSha256`; a pin that moved is `HARNESS_CORPUS_PIN_FAILED`, never replaced. `fetch.ts` downloads with `curl` into `<work>/<id>/<sha>.tar.gz`, checks the sha256, then the lockfile, each subject's directory and runner config, and an MIT licence file (root, or the first per-package one: date-fns; read by its exact tar member name, because `--include` is bsdtar's alone). `corpus pin <id>` takes repository ids only; a subject id or a typo is `HARNESS_USAGE`. `left-out.ts`: extraction leaves out `.env*`, `.vscode/`, `.idea/`, `.mcp.json`, repository configuration files and shell start-up files, because Claude Code's agent sandbox cannot write them; `FetchResult.leftOut` lists them.
- **Install.** `install.ts` runs the repo's own frozen install (`corepack pnpm@V install --frozen-lockfile --ignore-scripts`, `npm ci`, `corepack yarn@V install --immutable`), caches in `<work>/<id>/cache`, `HOME` and `TMPDIR` inside the work dir, then runs the repo's `rebuild` list, checks each subject's runner version and writes `install.json` with a fingerprint of every file under every `node_modules` (files are read 32 at a time). `reinstallOffline` deletes the `node_modules` trees, reinstalls with the network off inside the sandbox, runs the same `rebuild` list there, and requires the same fingerprint. `readInstallRecord` returns `undefined` (not installed) for a record whose `sha`, or whose extracted tree's `src.sha`, is not the manifest's pin, so a re-pin needs `corpus fetch` and `corpus install` again. The cache holds its own `package.json` (`type: commonjs`) because this repository's root says `module`, which breaks Yarn 4's `yarn.js`. An agent's sandbox cannot create the `.idea/` and `.gitmodules`-style files that some packages ship, so run installs from Tyler's terminal, or point `PROVINO_CORPUS_DIR` outside the checkout.
- **Sandbox.** `sandbox.ts` generates the Seatbelt profile (`(allow default)`, network denied but loopback and unix-domain sockets **under the run's own directory** (`writable`, as `subpath` rules), DNS mach services denied, credential paths unreadable, writes only to the run dir), the environment allowlist, and `evaluateProbe`, which fails closed. `probe-child.ts` makes the seven attempts (`tcp`, `dns`, `https`, `socket`, `canary`, `ssh`, `loopback`); `socket` connects to a unix socket outside the run's directories that `runProbe` listens on (`listenOutsideRun`, a short path under the system temp directory, closed afterwards; `ProbeOptions.listen` replaces it in tests), and it must be refused (a denial code, or the same connect working outside the profile as the control). A sandboxed test that needs a socket elsewhere fails with `EPERM` until the profile names it. Nothing here is applied by an agent: `sandbox-exec` cannot nest inside Claude Code's sandbox (it compiles the profile, then fails to apply it with exit 71 there; a profile that does not compile is exit 65). `runProbe` takes a `platform` option so its refusal off macOS is testable.
- **Tests.** `src/corpus/*.test.ts` and `commands/corpus.test.ts` use fakes from `corpus/test-support.ts` (a `CorpusDeps` that answers by command name, a repo entry, a tarball made with the real `tar`): `fetch` (real `tar`, fake `curl`), `pin` (fake `gh`), `install` (a fake package manager that rebuilds `node_modules`), `run` (a fake `runSubject`, `unsandboxed`), `gate`, `sandbox`, `manifest` and the command (refusals, skips, exit codes). The type tests are in `test/types.test-d.ts`.
- **Runs.** `run.ts` clones the installed tree (`cloneTree`: one `clonefile(2)` of the whole tree through `/usr/bin/python3` and ctypes, else `cp -cR`, else `cp -R`; `corpus run` tests once at its start whether the work root can clone and warns loudly with the reason if every run will copy every byte), runs `prepare` and `runSubject` (whose `wrap` option puts `sandbox-exec` around Node) inside the profile, and writes `run.json`, `meta.json` and the sidecar check under `<work>/<id>/runs/<subject>/<n>/`. `flaky.ts` (a status that differs between any two runs, absent included), `self-diff.ts` (run 1 against each later run, exact, console on, R2's limits, no unexplained diff), `gate.ts` (G0's report; the excluded share is `counts.excluded` over the reference's tests, the self-diff's and `diff --max-excluded`'s measure, D65, so a flaky key the reference lacks is not counted; 3 reference runs, `MIN_REFERENCE_RUNS`, which `corpus run --runs` also requires; self-diff pairs carry the run numbers on disk). `diff --suite` refuses a subject with no `flaky.json` (exit 2, "run corpus flaky first"), as `self-diff` and `gate` do. A run that fails removes its clone unless `--keep-tree`; the sidecar check reads the realpath of a symlinked work root as the conversion does.
- **Manifest rules and command shape (the simplify pass).** `install.version` is required and exact (`corpus pin` fills it from the tarball's root `package.json` `packageManager`, else from the lockfile's format marker through the tables in `pin.ts`; no installer default is left). A Jest subject's `provinoRefuses` must equal what `parseJestCli` (`@provino/dialect-jest/node`) reports as `JEST_CLI_UNSUPPORTED` for its `argv`, and the R6 repos are the ones whose subjects set `r6` (exactly 5, one subject each). `corpus run` probes the sandbox once per command. `fetch`, `install` (and `--offline`) and `clean` work on 3 repositories at once and print in manifest order; `run` never does. `fetch` remembers a tarball's entry list and licence verdict next to it (`<sha>.tar.gz.index.json`, keyed by the tarball's sha256), so a repeat fetch makes one pass. `run <subject>` runs that subject alone (`selectSubjects`). `readSubjectInputs` is the one reader of a subject's exclusions and flaky list (`diff --suite`, `self-diff`, `gate`), and R2's 0.02 is `R2_MAX_EXCLUDED_SHARE` in `internal/diff-bars.ts`. The online install's `rebuild` step runs under the sandbox, so a repository with a `rebuild` list needs Tyler's terminal for `corpus install`.
- **A flaky test that flips its file's status keeps a `file-status` diff** (flaky leaves T, never the file), so such a file needs an exclusion rule or a fix at the source.

## Shared with the bench

`@provino/bench` imports these from the package entry, so there is one of each:

- `spawnInGroup(command, args, { cwd, env, stdio, timeoutMs?, deadline?, killGraceMs? })` returns `{ child, exited }`. The child leads its own process group; `exited` settles after it exited and the group is gone (members left behind get `killGraceMs`, then SIGKILL). It installs no signal handler. `exitOnSignals()` is for entry points (`cli.ts` calls it).
- `runProcess(command, args, options)` is `spawnInGroup` plus captured output (the tail, a pipe grace, `wallMs`).
- `readRunEnvironment(runners)` and `resolveRunnerPackage(name, from)` replace the recorder's and the bench's own copies; `parseJestJson` and `parseVitestJson` read the runners' JSON.

- `pnpm test --filter @provino/harness`: unit tests (`src/**/*.test.ts`). They never start Jest or Vitest.
- `pnpm provino-harness record [--check] [<dir>...]`: record or check goldens. `pnpm record:runtime [--check]` is the runtime corpus; `pnpm record:expect [--check]` is the expect corpora. In CI it runs only when its inputs changed against main (`.github/actions/scope`).

## Gotchas

- **Jest runs fixtures as CommonJS.** Unless the fixture sets `jestEsm`, no ESM-to-CommonJS transform is installed (`babel-jest` alone only hoists `jest.mock`), so an `import` in a Jest fixture crashes the file (`Must use import to load ES Module`). In `*.jest.test.ts` use `require('./helper.ts')` (with an `as` type); `jest.mock` is hoisted above it. In `*.vitest.test.ts` use `import` and `vi.mock`. A shared `*.test.ts` can use globals only. With `jestEsm`, both runners can share ESM support files; load lazily with `require` under Jest and `await import` under Vitest.
- **A Jest transform error loses its stack and one line.** `jest-transform.ts` drops the stack of an error from Babel (it names this machine's `node_modules` and the transformer's own path, so the golden would leak them) and the `Allowed objects: ...` line of the out-of-scope error (the list follows the Node version). The message and its code frame text stay.
- **`jest.mock` factories may use pure constants.** `babel-plugin-jest-hoist` hoists a `const x = 'literal'` along with the factory, so `mod-factory-out-of-scope` uses `String('...')`, which it cannot hoist. A top-level `jest.fn`-free `mockCounter` function declaration is hoisted by JS itself and is allowed (`mock` prefix).
- **Where the two runners resolve differently (the `mod-*` slice).** A `vi.mock` of a relative path that is not on disk fails with `Cannot find module '/x.ts'` (a static import fails the whole file, `mod-virtual-static`); a bare name that is not installed works. `doMock` after a load gives the mock on the next load in both runners with no `resetModules`. Jest's non-hoisted unmock is `dontMock` (there is no `doUnmock`).
- **Node below 22.18** needs `NODE_OPTIONS=--experimental-strip-types`: the Jest child loads the `.ts` transformer through `require()`, and it inherits the environment. Not run on 22.15 here (Node 24.22 and 26.12 were).
- **`ExperimentalWarning: stripTypeScriptTypes`** appears on Node 24.22 in Jest's stderr. Harmless; the recorder shows the runner's output tail only when no JSON was written.
- **Biome skips `__goldens__/`** through `!**/__goldens__` in the root `biome.json`. Without it `pnpm format-and-lint:fix` reflows the arrays and `--check` reports drift.
- Jest's `--json` assertions carry `numPassingAsserts` and `failureDetails[i].matcherResult.name`, but its types omit them, so the converter reads them from `unknown`. Jest's file-level `message` prints paths relative to the root (`a.test.ts:7:23`); `userFrame` becomes `<root>/a.test.ts:7:23` either way.
- Jest `pending` is `it.skip`, `xit` and tests left out by `.only` or `-t`; the JSON can't say which, so `skipReason` is `unknown`. `focused` is a **file** status (passed, some tests didn't run).
- Neither JSON carries console output, so `console` is absent in goldens (the recorder doesn't use the sidecars) and in a conversion without `ConvertOptions.console`. `crashed` files take their `fileError` from the file-level message.
- **The sidecars.** Jest drops `testResult.console` once the reporters have seen it, so only a reporter can read it; `--silent` empties it, so `runSubject` passes `--silent=false`. Jest's entries carry a level (its `LogType` has no `trace`); the stream follows Node's `Console` (`warn`, `error`, `assert` and `trace` on stderr). Vitest's `onUserConsoleLog` has no level, merges adjacent writes to one stream, and reports a test's stdout before its stderr, so only each stream's order is defined; `taskId` resolves through `vitest.state.getReportedEntityById` to a test (per test, with `dupIndex` counted over `module.children.allTests()`), a suite or a module (per file). Each entry is split on `\n` and each line normalized with `normalizeText`, so a CR before a split newline stays (`crlf` can't fire on a console line).
- **`runSubject` flag order.** Jest's `--reporters` is an array flag that takes a test path after it, so the harness's flags go after the caller's argv. Jest also gets `--verbose=false`: `@jest/core` turns verbose on for a single test file, and a verbose worker writes console to the terminal instead of buffering it (30.5.2 still buffered when probed). `runSubject` removes the runner's JSON and sidecar from `outDir` before it starts, so a run that writes none fails instead of reading an earlier run's.
- **Test keys are unique by construction.** `testKey` joins the title path with ` › ` after escaping `\` and `›` inside each title (`keys.ts`), so different title arrays never share a key, and `dupIndex` counts tests with the same file and the same path array, as `@provino/types` documents. `describe('a', () => it('b'))` and `it('a › b')` are different tests (`a › b#0` and `a \› b#0`). `diffRuns` still throws `HARNESS_DUPLICATE_TEST_KEY` if a hand-built or foreign run repeats a key. A `null` in Vitest's `failureMessages` (`throw { status: 404 }`) becomes one error with the message `<no message>`.
- **A failed file with passing tests** (a hook after the last test) keeps its status and takes `fileError` from the file message, for both runners and both Jest shapes. When a test failed, the message repeats that failure, so there is no `fileError`.
- **Stack and frame rules.** A frame is `at <fn> (<loc>)` or `at <loc>`, with `<loc>` ending in `:line:col` or `<anonymous>`, `native`, `index N`; only the trailing run of frames is the stack (plus any run followed by a `[cause]:` or `Caused by:` line, Jest's cause chain), so frame-shaped text inside a diff stays in the message. The run's frames are indented alike: Jest's `toThrow` prints the received error's code frame and stack (6 spaces) right above its own stack (4 spaces), and that block, when it follows Jest's `Received message:` header (`Error message:` for a bare `.not.toThrow()`) with only blank and code-frame lines between, is dropped from both the stack and the message, so the user frame is the matcher call, as Vitest gives it; differently indented frame lines anywhere else stay in the message (B15; `expect/messages/throws` and `promises` were re-recorded for it). A frame is internal if it names no file (`<anonymous>…`, `native`, `index N`, an unreadable `eval at`) or its file path matches `node:`, `node_modules/`, `jest-circus` or `vitest/dist`; the function name is not looked at. An eval frame uses its origin. `internal/stack.ts` parses a failure once into segments (split at cause lines), each with its message lines and its frames. The path rules (ansi, crlf, file-url with 1-3 slashes, root, windows) run on the whole text, the code-frame, duration and placeholder rules on the message only, so `test/tmp/` and `10s.test.ts` survive in `userFrame`.
- **Narrow rules, on purpose.** `<root>` needs a path boundary on both sides (`/home/me/work/fixture`, `/work/fixture@1` and `/work/fixture copy/` are not the root). Durations are only `(12 ms)` and a `Time: 1.2 s` line, so configured timeouts and user strings stay. `<root>\n` is only converted to `/` when a configured root is a Windows path.
- **Parity counts.** `counts.excluded` is `referenceTests - comparedTests`: tests removed from T by a status or `missing-in-candidate` exclusion, or as flaky (`counts.flaky` of them). A test leaves F only when all its message-family diffs are excluded. The JSON guards check each file's status per runner, and Vitest's rejects Jest-only fields.
- Files in a converted run are sorted by path (runners list them in completion order); tests stay in declaration order.
- Vitest may print `ERROR: failed to copy trust settings of system certificate` on macOS. It is stderr noise.
- `diffRuns` drops an exclusion per diff kind, not per test: an excluded `message` diff never hides a `status` or `user-frame` diff on the same test. Console compares per test only when both runs attribute any; the concurrent-test multiset rule (R1) needs a marker the model doesn't carry yet. Jest attributes nothing, so a Jest reference compares every file's console as a sorted multiset, and hook order can't show (B15 gap 9).
- **Trace setup.** `internal/runner-config.ts` writes `.harness-out/trace-setup.ts` (Jest `setupFiles`, Vitest `test.setupFiles`). It has no import (Jest runs it as CommonJS) and uses `process.getBuiltinModule('node:fs')` with a synchronous append, so steps land in call order even for concurrent tests. The recorder, not the fixture's `env`, sets `PROVINO_TRACE_FILE`.
- **`.only` under the recorder's `CI=1`.** Vitest's `allowOnly` is `!isCI` (std-env also reads CI-provider variables), so `.only` is rejected: the `.only` tests carry the error and no test runs, but the file is not `crashed`. `only-scope` records that; Vitest's `.only` semantics with `allowOnly` on are not recordable here.
- **What Vitest's JSON drops.** Suite-level errors (a throwing `beforeAll`/`afterAll`, an empty suite) are not in the report: the file is `failed`, the tests keep their status, and `fileError` is absent. Jest's file message does carry them (`● Test suite failed to run`).
- A Jest describe with hooks but no tests makes the file `failed` and still runs its other tests, so it is not an `expectCrash` case; `test(name)` with no function, `test.todo(name, fn)`, an async describe callback and a describe callback that returns a value are.
