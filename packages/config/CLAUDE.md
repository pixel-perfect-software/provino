# @provino/config

Loads a project's config file and resolves it into everything the coordinator and its workers need (coordinator side; imports `@provino/types` and `@provino/policy` only). B11 built the first part of T1.4: `loadConfigFile`, `resolveProject`, `loadProject`. The built-in dialects and environments come from the caller (`provino`), so this package names no dialect and no environment package, and never imports one.

## Map

| Path | Role |
|---|---|
| `src/load.ts` | `importConfigModule(path)`: the one config-module loader (build-plan §6): a fresh `import()` of the file and its default export, unwrapped like `interopRequireDefault`; the Jest dialect's loader uses it too (T11.4). `loadConfigFile(path, env)`: that, then a (maybe async) function of `ConfigEnv` called; the result must be an object. `loadProject(path, options)`: load, then resolve (`env` defaults to `{ command: 'run', mode: 'test' }`) |
| `src/resolve.ts` | `resolveProject(input, options)` → `ResolvedProject` for a `provino.config.*`; `resolveNeutralProject(neutral, options)` → the same for a project a dialect's config reader produced (`ConfigReader.toNeutral`, B14b). Both parse their input, then share `finishProject`: policy layers, environment, isolation, setup files, the `SerializedProjectConfig` and its ref check |
| `src/errors.ts` | `ConfigError` with a `code` (`ConfigErrorCode`) and, for bad dialect options, `issues`; `formatConfigIssue` (the `  path: message` line, `(options)` for an empty path), used by the dialect-options message and by `provino`'s error text |
| `src/internal/input.ts` | `parseInput` (one `optional(input, key, expected, guard)` per key), plus the shared `isString`, `isStringArray`, `messageOf`: checks each key `resolveProject` reads (`CONFIG_INVALID`) and refuses `projects`, `plugins`, `alsoServe` when non-empty (`CONFIG_UNSUPPORTED`, naming T1.4) |
| `src/internal/dialect.ts` | `selectDialect` (by name, else by `detect`), `dialectPolicy` (a factory gets `config[name]`, checked by the dialect's Standard Schema first) |
| `src/transform-cache.ts` | `withTransformCache(project, dir)` (T3.6): wipes the transform cache directory when the lockfile changed, and returns the project with `config.loader.cacheDir = dir` (the original is untouched); `pruneTransformCache(dir)`. The orchestrator calls both; `@provino/transform` does the work. |
| `src/internal/refs.ts` | `assertWorkerConfig`: the finished `SerializedProjectConfig` is checked before `resolveProject` returns it (see "Refs") |
| `src/internal/transform.ts` | `resolveTransforms`: a neutral project's `transforms`, `transformIgnorePatterns`, `transformConfig` and `transformHoistedMarkers` as `loader.transform` (`SerializedTransformConfig`, T3.8), or `undefined` for none. Each rule's `module` stays an absolute path or `file:` URL; a bare name resolves from the project's root (`createRequire`, `CONFIG_INVALID` naming `transform[i]` when it can't); a pattern that isn't a regular expression is `CONFIG_INVALID` (`transform[i].pattern`, `transformIgnorePatterns[i]`). `assertWorkerConfig` checks each `transformer` ref like the others |
| `src/internal/setup-files.ts` | `resolveSetupFiles`: `setupFiles` entries to absolute paths, each checked to be a file |
| `src/internal/test-support.ts` | Temp dirs and `rejectsWith`, for the tests |

## Rules that aren't obvious

- **The config's keys are layered into the policy,** not only read beside it: `include` and `exclude` go over `orchestrator.include`/`exclude`, and `globals` over `core.injectGlobals`. The worker reads `policy.core.injectGlobals` *and* `config.globals !== null` (both must hold), so layering keeps the two in agreement. `ResolvedProject.include`/`exclude` are read back from the resolved policy.
- **Dialect choice:** a `dialect` name picks from the dialects the caller gave (a config's own `dialects` list *replaces* theirs, as `BaseConfig.dialects` says "default: the built-ins"); no name picks the highest `detect` score above zero; a tie is `CONFIG_DIALECT_TIE`, not a guess; no match is neutral (`dialect: null`, no globals). `detect` runs only when some dialect has one, and then reads the root's file names and `package.json` once.
- **Dialect options** reach a policy *factory* only (`config[dialect.name]`, through `dialect.options` when present, even when the value is `undefined`, so a schema can supply defaults). A plain policy never sees `config[name]`. `Dialect.policy` is typed bivariantly, so the compiler can't check the factory's argument: this validation is the check.
- **Environment:** the config's name, else `policy.orchestrator.envDefault`, looked up (own keys only) in the caller's table. `EnvironmentRef.options` is `{}`: config's `environment` is a name, so there are no options to give. (B10 noted `EnvironmentRef.options` and `EnvironmentOptionsMap` don't assign without a cast; nothing here builds one from the map, so the cast never came up. T1.4's `environment()` helper will meet it.)
- **Isolation:** the config's, else `isolationDefault.byEnvironment[env]` (own keys only), else `isolationDefault.default`.
- **Neutral projects (`resolveNeutralProject`):** the caller gives the dialect (the one whose reader produced the project) and the environments; the package still names none. The layers are the dialect's policy (a factory gets `undefined`), then `neutral.policy`. The project's `setupFiles` stay the worker's `setupFiles` (before the framework) and its `setupFilesAfterEnv` the worker's; each must be an absolute path to a file (`CONFIG_INVALID` naming `setupFiles[i]` or `setupFilesAfterEnv[i]`). `environment.options` reaches `EnvironmentRef.options`. `discovery` is carried to `ResolvedProject.discovery` (`null` for `resolveProject`). The orchestrator's `discoverProject` reads it (B14c): rules when present, `include`/`exclude` otherwise, and the results cache key includes it.
- **Global setup (T9.15):** a neutral project's `globalSetup` and `globalTeardown` (absolute paths, checked as the setup files are: a relative one is `CONFIG_INVALID`) become `ResolvedProject.globalSetup` (`ResolvedGlobalSetup`: `setup`, `teardown` and, from the reader, `args`, the two configs a Jest hook is called with as JSON, `NeutralProject.globalSetupArgs`); absent when the project has neither hooks nor args (a project with no hook of its own keeps `{ setup: [], teardown: [], args }` when the run has one, Jest's root `globalSetup` with `projects`, which is called with the first project's config). It stays on the coordinator side: nothing of it goes into `SerializedProjectConfig`, since the coordinator runs the hooks (`@provino/orchestrator`'s `runGlobalSetup`). A `provino.config.*` project has no such key yet.
- **Setup files:** the neutral `setupFiles` become the worker's `setupFilesAfterEnv` (as Track 11 maps Vitest's); the worker's `setupFiles` stays `[]`. An entry is a relative path (`./`, `../`) or an absolute path, resolved against `rootDir`, or a `file:` URL (through `fileURLToPath`). Anything else (a bare package specifier such as `@testing-library/jest-dom/vitest`, a `<rootDir>` token, `nested/x.ts`) is `CONFIG_INVALID` saying package specifiers aren't supported yet (T1.4). Each result is `stat`ed and must be a file, else `CONFIG_INVALID` naming the entry (`setupFiles[i]`).
- **Root:** `rootDir` must be an existing directory (`stat`), checked in `resolveProject` and reported before any other failure (it runs beside `detect`'s read of the root, and its error wins if both fail), whether or not a dialect has `detect`. A missing root would find no tests, and `passWithNoTests` would exit 0.
- **Refs (D21):** `assertWorkerConfig` runs last. Every `{ module, export }` ref in the serialized policy, `globals` and `environment` must be a plain ref whose `module` is an absolute path or a URL (`isImportableLocation` from `@provino/policy`, the rule the worker's config check uses too; the walk over the policy is policy's `forEachModuleRef`, here with a looser guard so a malformed ref is reported, and a function stops it), and a function anywhere in the policy is refused; each is `CONFIG_INVALID` naming the key path (`policy.core.formatEachTitle.module`, `globals.module`, `environment.module`). Then the config is `structuredClone`d and a `DataCloneError` is `CONFIG_INVALID`. So a dialect's bare or relative ref fails as exit 2 here, not as exit 1 in every worker.
- **Loader extensions:** `.js .mjs .cjs .jsx .ts .mts .cts .tsx .json` (Jest's `moduleFileExtensions` order without `.node`; a neutral default of ours), a fresh frozen array per project.
- **Mock hoisting and per-module bindings (B13c):** the dialect's `loader.hoist` goes into `SerializedLoaderConfig.hoist` by value (data with `RegExp` and `Set` leaves, which clone; `null` with no dialect or none), its `moduleScope.names` into `loader.moduleScope` (`[]` for none, and `[]` when `core.injectGlobals` is off, so a module's wrapper declares no `jest` and a use is Jest's `ReferenceError`), and its `moduleScope.factory` ref into `SerializedProjectConfig.moduleScope` (`null` for none), whether or not globals are injected (it also serves `@jest/globals`). `assertWorkerConfig` checks that ref like the globals one (`moduleScope.module` absolute, D21).
- **Config modules compiled from `export default`** (CommonJS with `__esModule` and an own `default`) are unwrapped as Jest's `interopRequireDefault` does, so tsc/Babel output isn't an empty config.
- **Detect sees symlinks to files** (`stat`), not dangling links or links to directories. Dialect options are read from an own key of the config only.
- **Resolver keys (T3.3):** a neutral project's `aliases` and `resolution` (`moduleDirectories`, `modulePaths`, `resolver`) go to `SerializedLoaderConfig.aliases`, `.moduleDirectories`, `.modulePaths` and `.resolver` (a ref with export `default`), left out when empty. The worker's loader builds the name mapper from `aliases`, so this package needs no edge to `@provino/resolver`.
- **Loader conditions** come from calling the policy's `orchestrator.environmentConditions` behaviour in the coordinator, with the environment's *name* only. An `Environment` object's own `conditions` live in the worker and are not seen here.
- **Every failure is a `ConfigError`.** Policy errors (`resolvePolicy`, `serializePolicy`), a throwing dialect `detect` or factory or schema, and an unloadable behaviour are wrapped with the original as `cause`.
- **Every load reads the file again.** Node caches an import by URL, so `loadConfigFile` imports `file:///…/config.mjs?provino-load=<uuid>`: a URL of its own per call, which reloads `.mjs`, `.mts`, and `.js`/`.ts` under a package of `type: module` (checked on Node 24.22). Node's CommonJS loader ignores the query and keys by file name (`.cjs`, `.cts`, `.js`/`.ts` under `type: commonjs`), so the file's `require.cache` entry is deleted first (`createRequire(import.meta.url).cache`). Limits: each load stays in the ES module map for the life of the process (a small leak, accepted for config files), and only the config file itself is reloaded: a module it imports or requires keeps its cached copy, so edit-and-reload of a helper needs the process to restart. A config *function* runs on every call either way (it is called with `env` each time), so one that reads `process.env` always sees the current value; module-level code reads it at load time, and now does so per load. `import.meta.url` in the config carries the query; `import.meta.filename` and `dirname` don't.
- Tests use small fake dialects (`defineDialect`) and real config files written to `$TMPDIR` at test time (no `.js` is committed, D13). The package may not import `@provino/dialect-jest` (not in its manifest deps), so the real Jest dialect is exercised in `provino`'s tests.

- `tsconfig` / `mappers` / `typescript` options (the loader block is the bench's defaults, with `tsconfig: 'auto'`); resolver aliases (T1.4, U9).
