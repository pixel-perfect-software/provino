# @provino/reporters

The reporter bus and the built-in reporters (coordinator side; imports `@provino/types` and Node builtins only): the text ones (`default`, `verbose`, `dot`, `agent`), `json` (`normalized-json` is the same reporter), `junit` and `github-actions` (T9.7, B21c), and, as entries of their own loaded only when chosen, `@provino/reporters/live` (the `provino` reporter) and `@provino/reporters/html` (the static HTML report). It reads the `report` policy slice, and only through each reporter's `report` option.

## The live views (`--tree`, `--map`; B26 Phase 4)

`ProvinoReporterOptions.views` (`{ tree?: true; map?: true }`, `ProvinoViews`; `provino`'s `ProvinoChoiceOptions` is an alias of it) turns on two blocks the `provino` reporter prints at `run:end`: **the tree after the run's lines and before the end card, the map after the end card** (printed as plain lines without a terminal, and into the same last write as the card on one). **Every block of the run's end, the card included, goes through one `append(block)`**: it leads the block with exactly one blank line, adding none when the last line handed over (queued in `pending`, or already written: `lastTaken`, kept by `takePending`) is blank, and drops the block's own leading blank lines, so a failure block's trailing blank is never doubled. With neither view nothing is kept and nothing printed beyond that rule: `views: {}` is byte for byte the run without it.

- **The tree store is built only under `--tree`** (`createLiveReporter(options, state, makeTree = createTreeStore)`: the third argument is the seam `reporter.test.ts` probes, so a run with no `tree` never calls it, and the reporter has no `file:collected` handler at all). A running file's record is the collected `tasks` array (the event's own, not copied) and, per test that ends, three pushes on parallel arrays (`task:end` makes the one `testEnd` call; a suite that ends `fail` calls `suiteFailed`): constant work per event, no string, no width. `compact(finished)` runs in the `file:end` handler, on the record `state.fileEnd` returns, **apart from the live ring**: the views never depend on a frame admitting the file, so a run longer than the ring (4,096 files between frames) still lists every file, and a record never outlives its file (`held()` is the running files'). A file that fully passed costs a map delete; a file with a failure costs one walk of its own tasks, the one place a handler does more than constant work, only under `--tree` (the bench's `--tree` signal). **A file that fully passed keeps its numbers only** (`TreeFile.open` is absent; its tasks and results are released), **any other file keeps its suites with their counts and times and only its failed tests**, each with the first line of its error (`header`'s rule from `text/format.ts`: `Name: first line`, no name for a plain `Error` or a message that starts with it), copied flat (`copyFlat`, `bound.ts`) so the whole message it was cut from is not kept alive. **Everything kept is bounded:** at most `MAX_TREE_FAILURES` (50) failed tests listed per file, the rest counted (`OpenFile.moreFailed`; a failed test inside a suite that is not listed counts there too), and a file holds only that many errors while it runs (the first that end), so a file with 5,000 failures holds 50 stacks; at most `MAX_TREE_SUITES` (50) suites listed under one suite or file, the rest counted into the totals and one `… N more suites` row (`moreSuites`), and only that many suite errors held. A suite whose own hook threw (`suite-end` `fail`) is a failure for every suite above it and for the file, so the tree opens down to it, and a file with one is never taken as fully passed whatever its own state says. A suite's state is `outcomeOf` over everything below it, `todo` carried as a subtree total like `skipped`, so a suite that holds only a nested todo suite is todo as a file of the same is. A suite with no failure is one folded node with nothing below it; an open suite's passing, skipped and todo tests are one `TreeRest`. A record is made by `collected` only, so a late `task:end` for a file already compacted makes none; `clear()` empties it at `run:start` and `run:end`. `task:end` for a test fires once per test however many attempts it had (the attempts are `test:attempt-end`; `reporters.test.ts` runs `jest.retryTimes` through the bin to pin it), so the store keeps one entry per test.
- **Every file that ended is one `FolderFile` row** (`fileOutcome(finished)`: run path, project, `kind` `pass`/`fail`/`skip`/`todo`, counts, time; `todo` is the one new counter the state keeps per file, a part of `skipped`) in `viewFiles`, pushed in the `file:end` handler for `--tree` (`trees.compact(finished)`) or `--map` (`fileOutcome(finished)`), cleared at `run:start` and `run:end`. The path is `FileInfo.runPath ?? path`, POSIX upstream (the orchestrator's `relativePosix`). The live lines still say `… N more files finished` when the ring drops some; the views are complete and carry no such note.
- **`internal/views/folders.ts`** (shared with Phase 5's time by folder; pure): `outcomeOf(tests, failed, skipped, todo)` is the one rule for how a set of tests ended (a file's kind, a suite's state) and `fileKind` adds the file's own state; `groupByFolder(files)` groups by project and `posix.dirname` of the run path (`.` for a root file) into `Folder`s in code-unit order, files in path order, with totals and time; `folderLabel` (`web src/cart/`, `./`) and `folderDetail` (`4 files · 11 tests · 3 failed`) are the folder heading's wording.
- **Shared view helpers:** `markOf(kind, glyphs)` and `plural` in `live/view/format.ts` (the one glyph rule and the one count-and-noun rule, used by the file line, the end card and the tree; `plural` and `groupDigits` are defined in `internal/views/count.ts` so the folder helpers can use them, `internal/` never importing `live/`), `fileDetail` in `view/file-line.ts` (it takes the kind), and `oneLine` in `terminal/sanitize.ts` (`cleanText` without colour, then each run of newlines and tabs one space: names and messages in a row).
- **`view/tree.ts`** (`treeLines`): a folder is a heading with its files under it, drawn with `Glyphs.tree` (`├─ └─ │` in the emoji and unicode sets, `|- \- |` in ascii; each `GUIDE_WIDTH` = three columns); a fully passing file is one folded row, any other opens to its suites and failed tests, a failed test followed by a dim line with its error's first line, then one row for the tests not listed (`✅ 8 more tests · 2 skipped`) and the `… N more` rows. **Every row's time is right-aligned in the last column**, a long name is cut so the time stays, no row is wider than `columns - 1`. Widths are measured once: a guide is `GUIDE_WIDTH` a level (`depth`), a mark's width is per kind (`Context.markWidths`: the ascii set's `ok` and `x` differ), a label and detail are measured once and again only when cut, a time is ASCII, and a message is fitted to what its prefix leaves and then prefixed, so a plain message stays on the ASCII fast path. `view/map.ts` (`mapLines`, `mapLegend`): a legend, then a row per folder (label cut from the left to 40% of the width, cells wrapped under it); a cell is `Glyphs.cell` (`🟩🟥🟨⬜` in the emoji set, `.` `X` `s` `t` coloured green, red, yellow and dim elsewhere, so it reads without colour); the row wraps by the widest cell of the set and is cut with `fitWidth` like the legend, so none can wrap; no folders, no lines.
- **Goldens:** `provino-{tree,map}.{emoji,fallback}.{40,120}.txt` and `provino-{tree,map}.colour.120.txt`, the whole run (so the placement shows) over `VIEW_FILES` in `live/goldens.test.ts`: the fixture's files laid out in folders plus a failing file with nested describes and a folder of 18 small ones, the failing `broken.test.ts` last, played with `live: false`. `steppedBus` (`live/test-support.ts`) is the one stepped bus the goldens and `reporter.test.ts` play runs through (it moves the clock 37 ms an event and, after a file, lets reads settle and draws a frame: nothing after the tick is awaited, because the goldens pin how many microtask turns a code frame's read gets). Not built: the plan's "unless `--tree` with `--verbose`" (every passing file unfolded): the reporter has no verbose option, and `--verbose` keeps Jest's reporter (D143).

## The HTML report (`@provino/reporters/html`, B26 Phase 5)

The page's design authority is `DESIGN.md` beside this file (the Profiler Panel design system); `PRODUCT.md` is its brief and `.impeccable/` holds its direction contract and sidecar.

`htmlReporter({ outputFile, root?, now?, wallClock?, seed?, sample? })` (`@beta`) writes one self-contained page at `run:end` with `writeAtomically`, never to a stream. It is a document reporter over the shared collector (`console: false`): a file's tests, failures and own errors become compact rows when it ends and its record is released (`reporter.ts`: `compact`), so what it keeps is rows over one string table, not trees. **`data.ts`** is the pure part: `createStringTable`, `failureText` (`formatErrors` as the text reporters print it, the run's root taken out of every path, colour codes and control characters dropped, at most `MAX_FAILURE_TEXT` = 16 KB), `MAX_FAILURES` = 1,000 (the rest are counted in `ReportData.omitted`, their tests listed without text), `serializeData` (`<`, U+2028 and U+2029 written as `\u` escapes). The rows are typed in `page/model.ts` (types only, shared with the page's project): files `[pathId, status, ms, workerId, startMs, endMs, expectedMs, projectId]` in the order they ended, tests `[fileIndex, titleIds, status, ms]`, failures `[testIndex, text]`, file errors `[fileIndex, text]`, run errors, the snapshot totals, the run's `root` and, when given, its `seed` and a `sample` mark. **The timeline is stamped by the reporter (D139):** `now()` at `run:start`, `file:start` and `file:end` (the test counts the reads: one each), with the `workerId`; a replaced worker has a new id. A file in the summary that never had a `file:end` gets a row with no worker or times at `run:end`. **`render.ts`** writes the document: a CSP `<meta>` (`default-src 'none'; style-src 'unsafe-inline'; script-src 'sha256-<hash of the script>'; img-src data:`), the styles, the data as `<script type="application/json" id="provino-data">` and the page script, `renderReport` from `page/main.ts` written with `Function.prototype.toString()` (`pageScript`: comment lines, indentation, trailing spaces and blank lines dropped, which is why `main.ts` has no multi-line template literal and no comment after code; it throws on text that would end its `<script>`).

**The page script (`page/main.ts`, its own `tsc -b` project: `lib: ["es2023", "dom"]`, `types: []`, referenced from the package's tsconfig, which excludes `src/html/page`)** is one function that closes over nothing, so it works from source (Node's type stripping) and from the build (the umbrella's `html` chunk, not minified) with no bundler step and no `.js` file (D138); the jsdom test (`page.test.ts`, jsdom a devDependency of this package only, D148) runs it from source and `packages/provino/test/exports.test.ts` runs the built page's script. **Its design authority is `DESIGN.md` beside this file** (the Profiler Panel; `PRODUCT.md` is the brief and `.impeccable/` holds the direction contract and the design system's sidecar): change the look there first, then `page/styles.ts`. The page is, top to bottom: the verdict bar (the headline with 💥 or 🎉, then the fixed fields: Failed, Passed, Skipped, Todo, Files, Time, Workers, Seed, Snapshots, Failed first on a failing run), the run overview (an SVG of every worker's files along one axis, each slice painted by its status: a folder hue for passing work (85° to 320°, never red), `#p-fail` hatch, `#p-crash` cross-hatch, `#p-skip` dots, a todo outline; a pointer brush, and a "Select range…" form with From and To in seconds for the keyboard; the range filters every view, which re-renders), the sticky tab bar (with the run's root and start time, and "sample data" only for a sample run) and five views in a `role="tablist"`, each built when first shown: **Failures** (a row for each failed test and each file that failed or crashed on its own, the first expanded as a code frame coloured by line kind, with "Show in Tests" and "Show on worker N"; the run's own errors; the `omitted` note; it opens first on a failing run, Tests on a passing one), **Tests** (the `role="tree"` with a roving tabindex and Up/Down/Left/Right/Home/End/Enter, folded where everything passed, failures open with boxed code frames, **each level built as it is opened**, so 50,000 tests are not 50,000 nodes; search over the paths and titles debounced 150 ms, at most 500 results, the Failed, Skipped and Todo chips, a `role="status"` count), **Map** (a patterned square for each file by folder in one `role="group"` described by its help line, one roving tab stop, arrow keys including Up and Down by visual line, Home and End, Enter to reveal), **Folders** (a table sorted by time, folder-hue bars hatched for a folder with a failure, Time, Share, Files, Slowest file) and **Timeline** (a lane for each worker, "N% busy", a replaced worker labelled "took over from M", an SVG sized to its container with a `<title>` on each slice and failed or crashed slices in the tab order, and "Show as a table"). The SVG namespace is read from the parser so the document holds no URL, text goes in with `textContent` and `append` only, and every status is a glyph with a `sr-only` word as well as a pattern. `page/styles.ts` holds every colour, size, spacing and duration as a custom property on `:root` (dark values under `prefers-color-scheme`), and its class names are the hooks (listed at its top); `styles.test.ts` holds the tokens to AA contrast in both schemes and checks that no rule carries a colour, length or duration of its own.

`sample.ts` is a seeded sample run of app-500's shape (500 files of 8 tests over 12 folders and 8 workers, the fixture's 1% failure rate and shapes; `failures` adds a nested file and a file that fails to collect, `crashed` and `2000-files` a file whose worker died (and a replacement worker) and an error that belongs to no file) played through a bus on a clock it moves: `src/html/sample-cli.ts` (`pnpm --filter @provino/reporters html-sample <dir> [state…]`, or `node packages/reporters/src/html/sample-cli.ts <dir>`) writes each state to `<dir>/<state>/index.html` to serve with `python3 -m http.server --directory <dir>`. `test-support.ts` has the fixture run with workers and times (`TIMED_FIXTURE`), `playTimed` and `reportFor`. `pnpm bench:reporter html` holds the bars (`packages/bench/src/reporter/html.ts`).

## The bus

- Reporters get an event in registration order, each handler awaited before the next. **Events are delivered one at a time** in the order `emit` was called (an internal promise chain), so no reporter ever runs two handlers at once, and a slow reporter slows whoever emits (the workers, through the pack window). A reporter must not `await` the bus from a handler: it would wait on itself.
- A handler that throws or rejects never fails `emit`. The error is recorded and sent to every *other* reporter as `error(err, 'reporter')` **right after that handler fails, before the remaining reporters get the event**; one that throws on *that* is recorded but not announced again. `failures()` is the recorded errors in order, then each reporter's `lastError()` as of the call; the coordinator turns a non-empty list into a failed run.
- So a reporter registered *after* a failing one sees the failure before the event, and one registered *before* it sees the failure after. A reporter that must record a failure at `run:end` (normalized-json) has to be registered last; `provino` does that.
- A reporter added during an `emit` first sees the next event.

## The text reporters (`default`, `verbose`, `agent`, `dot`)

One engine (`createTextReporter`), four modes. A mode is a row of traits, not a name the engine compares. A run's state lives in the closure and `run:start` resets it; a file's is one record of the shared collector (`console` kept only for a mode that prints it and not under `silent`), made on first touch and released at `file:end`, so an event for a file that has ended is dropped. The totals count at `task:end`, so a file that never ends still counts its tests. Options (`TextReporterOptions`): `stream`, `report`, and `colour`, `live`, `columns`, `silent`, `noStackTrace`, `expand`, `verbose` (only `false`), none on by default; `provino` fills them from `detectOutput` and the Jest flags.

- **The header is Jest's** (recorded: `cli/report-default`): `PASS ./a.test.ts` with `./` before a file in the project's own directory (`src/a.test.ts` stays), no timing unless the file took over 5 s (`PASS ./slow.test.ts (7.234 s)`, Jest's `slowTestThreshold` default; the config key is not read), a project's `displayName` before the path (`PASS server ./a.test.ts`, B17d), and **no line for a file whose every test is skipped**. The reporter prints `FileResult.state` and does not second-guess it: a file with a `todo` test is `PASS` under Jest because the orchestrator decides so once (`orchestrator.todoOnlyFile`, DV50, B21c), and the totals count it as passed. With `colour`, `PASS`/`FAIL`/`RUNS` are inverse bold badges (` PASS `), the counts have Jest's colours.
- **Failures:** a failed test's title (the policy's bullet and separator) with its errors, kept from `task:end` until `file:end`; so are suites that end `fail` with errors of their own (an `afterAll` that threw, under `hooks.afterAllError: 'fail-suite'`), titled with the suite's name path (built from that file's `file:collected` tree only when the suite failed). A file's own errors (a collection error, a worker crash) print under "Test suite failed to run", or "Errors outside the tests" when tests failed too. An error prints its message (`Name:` in front unless it is `Error` or the message already starts with it), the stack's `at` frames minus `node:` and `node_modules` ones (Jest's `removeInternalStackEntries`; none at all under `noStackTrace`), then its `cause` and aggregated `errors` nested (three levels). The message is Provino's own text, not claimed to be Jest's: Provino's frames differ.
- **Console** (`console` events): kept per file until `file:end`, printed under the header as Jest's block: `  ● Console`, then `    console.log`, the message six deep, a blank line. A direct stream write is `process.stdout`/`process.stderr`. `warn` is yellow, `error` red. The worker captures the call site when the policy's `orchestrator.consoleOrigin` is `stack` (Jest; recorded in `cli/report-default`): the call's `at` line (a `warn` or `error` carries the whole stack, 10 frames, which the dialect's `consoleTrace` filters and renders), printed after a blank line at 6 spaces, under `--noStackTrace` too (Jest keeps the first path line), with a path made relative to the run's root only where it starts; under `none` the events carry `origin: null` and no line prints. `silent` prints none; `agent` and `dot` print none.
- **`verbose`:** as `default`, with the file's tests listed under the header (`verboseList`, recorded in `cli/report-verbose`): a suite's own tests first, then its inner suites, two spaces a level, `✓ ✕ ○ ✎`, `(3 ms)` after a test that took a whole millisecond, skipped and todo tests after the others as `skipped <title>`/`todo <title>` (`expand`: declaration order, plain titles), a blank line after the list. The console blocks come **before** the header, two spaces in, as Jest prints them live. A test that never ended and a suite with none that did are not listed.
- **`agent`:** only failed files (header and failures) and the totals; nothing for a pass, no console, no live block.
- **`dot`:** `.` passed, `F` failed, `-` skipped or todo as each test ends, wrapped at `columns` (as `detectOutput` reports it: a whole number of at least 1, so a stream with `columns: 0` is 80 there, and the engine takes it as given). The marks are held and written when a row is full, when a file ends and before any other write (an `error` event, the totals), so a file is a few writes, not one a test; then a blank line, the failed files as `agent` prints them, and the totals. An `error` event during the run ends the row of dots first and prints its block under a blank line.
- **The live block** (`live`: `detectOutput` says a terminal that is not CI, not dumb, not an agent's; never in `agent`, and never in `dot`, whose row of dots the redraw would erase): `RUNS ./path` for up to four running files and `... and N more`, redrawn with `ESC[nF ESC[0J` (up n lines, erase down) as files start and end and before any text is written above it, erased at `run:end`. A name is cut to the width (each `RUNS …` line is rendered once, when its file starts). A file that ends is erased, its text written and the block drawn again in **one write** (`LiveOutput.finish(id, text)`), and a redraw that would draw the block as it already is writes nothing. With no block (not `live`, or `agent` or `dot`) there is no `file:start` handler at all.
- **The summary is Jest's `getSummary`** (B21a): a count of zero is left out (`Test Suites: 1 failed, 1 total`; the `total` stays), and the suites read `N of M total` whenever the suites that ran (failed plus passed, so not a skipped file) differ from the files `run:start` announced: a run that bailed (`1 of 3 total`) and a run with a skipped file (`1 skipped, 1 passed, 1 of 2 total`), both recorded from Jest (`cli/bail-one`, `cli/skipped-file`, `cli/skipped-file-alone`). Then unhandled errors from `RunSummary` that no file's text showed (a file's record takes only an error charged to the file or one of its tasks: one charged to another file's task, reported while this file ran, is the run's; one shown under the test it was charged to, or held by a dialect's `failureText`, which takes every error of its file, is not printed again), the obsolete snapshots by file (`obsoleteBlock`), `Test Suites:`, `Tests:`, Jest's `Snapshots:` line (`snapshotLine`: zero parts left out except `total`; absent when no snapshot was checked, written or obsolete), `Time:` (`RunSummary.durationMs`; the reporter has no clock). Not printed: Jest's `Ran all test suites.` line and its per-file snapshot lines (` › 1 snapshot failed.`) and `Snapshot Summary` block (T11.9). Counts come from `test-end` events; a test that never ended isn't counted. After the summary, `RunSummary.openHandles` (when there) prints as Jest's report (`openHandlesText`: the count, each handle's `●  <kinds>`, its code frame indented 4 and its frames 6). **The wording says "Jest" for every dialect** (DV48): there is no policy key for it until T11.16 has a Vitest reporter text to record.
- **Jest's single-file rule** (`runJest`: `allTests.length === 1 && silent !== true && verbose !== false` on the global config, so a `verbose` that is unset is not false): the policy's `report.listTestsForSingleFile` (Jest `true`, neutral and Vitest `false`) makes `default` list the tests, with the console block before the header, as `verbose` does, when `run:start` announces exactly one file (counted at `run:start`, so a second file that never ran still makes two; a run of none is not one). Jest's two exceptions are plain inputs: `silent`, and `verbose: false` (the option `verbose`, set only when the config says `false` on purpose). Any project under the Jest dialect gets it, through `provino jest` or `provino run --config`. Recorded in `cli/report-single-file`, `report-single-file-silent` and `report-single-file-verbose-false`.

- **`summary` and the pieces a dialect adds (T11.9, B23a).** `summaryReporter` is the summary alone (the engine's `summary` mode: nothing per file, the failed files' text kept for "Summary of all failing tests" past `failureSummaryThreshold`, the snapshot summary or `obsoleteBlock`, the totals, `closingLine`; nothing for a run of no files), after `default`/`verbose`/`agent` given `summary: false` (which still print unhandled errors). `failureText(file)` replaces Provino's failure blocks for a failed file with the dialect's text as `FailureTextBlock`s (one per failed test, by `taskId`, then the file's own errors), printed joined by `\n` with each test's `lazyBlock` after its own block; `snapshotsAlways` prints `Snapshots:   0 total`. Provino's own frames (a workspace checkout's `packages/<name>/src|dist`; an install's are under `node_modules`) are left out of every frame list (D104). `consoleTrace(file, entry)` (T11.9) replaces a console entry's `at` line with the dialect's own text (Jest's `formatStackTrace`: a code frame for `warn` and `error`, then the frame), printed dim under the message; `ConsoleFormat.trace` is the same for `consoleEntries`.

## `detectOutput` and the environment

`detectOutput({ env, stream, ci, colour })` is a pure function (callers and tests pass the environment and the stream). `colour`: `FORCE_COLOR` (anything but `0`/`false`) is on and wins over `NO_COLOR`; a non-empty `NO_COLOR` is off; otherwise a terminal that is not `TERM=dumb` and not an agent's (escape sequences are noise to what an agent reads). **CI alone does not colour** (Jest's picocolors does, DV47). `live`: terminal, not dumb, not `ci`, no agent. `agent`: `AI_AGENT` (its value names the agent) or one of `AGENT_VARIABLES` (std-env 4.3's `detectAgent`: `CLAUDECODE`, `CLAUDE_CODE`, `CURSOR_AGENT`, `CODEX_SANDBOX`, `CODEX_THREAD_ID`, `GEMINI_CLI`, `COPILOT_AGENT`, `COPILOT_CLI`, `AUGMENT_AGENT`, `GOOSE_PROVIDER`, `JUNIE_DATA`, `JUNIE_SHIM_PATH`, `OPENCODE`, `REPL_ID`) set to something that is not empty, `0` or `false`, plus the three patterns (`PATH` has `.pi/agent`, `EDITOR` has `devin`, `TERM_PROGRAM` is `kiro` without a terminal). Choosing reporters from it (`agent` for an agent, `github-actions` added on GitHub Actions) is `provino`'s `reportersFor`, not this package's.

## `junit`, `github-actions` and `json`

- **`junitReporter`** writes one document at `run:end`, to `outputFile` (atomically) or `stream`: `<testsuites name tests failures errors time>`, a `<testsuite>` per file (`name` the path with the project before it, `file`, `tests failures errors skipped time timestamp`), a `<testcase name classname time>` per test (`classname` the file's path, `name` the titles joined by the policy's separator; a failed test has `<failure message type>` with the errors as text, a skipped or todo one `<skipped message>`, a test that never ended `<skipped message="not run">`, its console `<system-out>`/`<system-err>`). A file's own errors (it did not run, a worker died, an `afterAll` threw) are an `<error>` on a testcase of their own; errors outside any file are a suite of their own. Text is cleaned (ANSI and the characters XML 1.0 forbids dropped; text with none is returned after one test). Each file's `<testsuite>` is written as XML when the file ends and its record freed (`release`), and the suites are joined in `summary.files` order at `run:end`; an error charged to a file after it ended is one of the run's errors, as its suite is written. **The output is validated against `vendor/junit-10.xsd`** with `xmllint-wasm`'s `validateXML` (libxml2 as WebAssembly, a dev dependency: no system `xmllint`, so CI and every machine use one validator) in `junit/reporter.test.ts`, and a mutated document is refused, so the check is real. The testcase has no `file` or `line` attribute there (the schema has none).
- **`githubActionsReporter`** prints `::error file=,line=,col=,title=::message` per failed test as its file ends, per file that failed to run, and for `error` events and run-level unhandled errors (no file). The location is the error's own `location`, else the first stack frame that is not Node's or a library's, else the test's, else the file alone; paths are relative to `workspace` (`GITHUB_WORKSPACE`) when given. Data and properties are escaped as `@actions/core` does. It keeps no console output, frees a file's record as the file ends, and takes nothing more for a file that has ended (no record is made again) except an unhandled error: that one is annotated on the file at once, titled with its path.
- **`jsonReporter`** is `normalizedJsonReporter` with the name `json`.

## The normalized-json reporter

- Identity is the file path, `TestTask.fullName` and `dupIndex`. Tests are listed in declaration order by walking the tree from the file node, since `file-collect-end.tasks` is only "parents before children". A test collected but never ended (or ended `queued`/`running`) is `notRun` with no assertion count or duration.
- A file with `workerExit`, or one that failed with no tests collected, is `crashed`; otherwise `failed`/`skipped`/`passed` from `FileResult.state`. `fileError` is the file's own errors, the errors of its failed suites (`suite-end` with `state: 'fail'`) and the unhandled ones charged to it (several are joined). An unhandled error tied to a file is added to that file (and fails a passing one); one tied to no file, and every `error` event, is a `runErrors` entry. One charged to a test of the file (`ownerId` is a collected test: Jest's `errors.lateErrors: 'fail-owner'`, T5.11) is that test's failure instead: the test is `failed` with the error appended to its own, and its file `failed`, with no `fileError`. The default reporter prints it under that test and moves it from passed to failed in the tally.
- `success` is false for a failed or crashed file, a run error, or a run whose `reason` isn't `passed` (an `interrupted` one, or one the orchestrator failed on its snapshots with every file green). `snapshots` is `RunSummary.snapshots`' totals and the `.snap` files the run left, each with the sha256 of its bytes and its path POSIX and relative to `run:start`'s `root` (`normalizeSnapshots`; a file that can't be read is left out); `trace` (T12.7) is left out. `expectedToFail` and `location` are filled the way the harness's Jest converter fills them. `retries` counts `test:attempt-end` events with `willRetry` (real retries only: `TaskResult.attempts` also counts repeats); without any attempt events it falls back to `attempts - 1`, unless the test repeated, when it is left out.
- **Console** (B15): every `console` bus event is kept in the file's record and written split on `\n` (a trailing newline ends the last line, so `console.log('')` is one empty line), with `stream` and `level` (none for a direct stream write). A write whose `taskId` is one of the file's tests goes on that test, its each-hooks included; a suite's or the file's `beforeAll`/`afterAll`, the top level and a write outside any task go on the file. A file or test that wrote nothing has no `console` key. The text is as the worker captured it: the harness's `convertProvino` normalizes it.
- `unhandledErrors` (`'fail-run'` default, or `'ignore'`) mirrors the orchestrator's policy: under `ignore` unhandled errors are still recorded (`fileError`, `runErrors`) but fail neither a passing file nor `success`. `error` events (including `reporter` ones) always count. `provino` passes the policy's value.
- `outputFile` is written to `<path>.<pid>.<random>.tmp` beside it and renamed over it, so concurrent runs and a kill mid-write never leave corrupt JSON; a failed write removes the temp file.
- `env.ci` is the `ci` option when given (over `env.ci` of an `env` option too): `provino`'s `run()` passes the ci it resolved, so the file agrees with the run. Only without one does the reporter read `CI` itself, by the same rule.
- `startedAt` is the wall clock at `run:start` (`now`, default `Date.now`). A failed write throws out of `run:end`, so the bus records it and the run fails.
- The tests assert the JSON's shape directly: `parseNormalizedRun` lives in `@provino/harness`, which this package's manifest node may not import. B11's bench check runs it on real output.

- **Lazy values (B24e, T6.10):** a failed test whose `TaskResult.lazies` is set gets `lazyBlock` (`format.ts`) under its errors, in all four modes (they share `failuresOf`), and under a dialect's `failureText` after that test's block: `Lazy values evaluated before the failure:`, then each value in the order it finished with `(override)`, `threw`, its definition site (relative to the run's root) and its time, then one `chain: cart -> user` line per distinct chain of a definition that threw. Provino's own text, not claimed to be Jest's. Its goldens are `lazies.{plain,tty}.txt` from `text/lazies.test.ts`, apart from the fixture run's.

## Goldens

`builtins.test.ts` plays the fixture run (`FIXTURE_FILES` in `internal/test-support.ts`: a pass with nested describes, a failure, a skipped and a todo test, a file of only skipped tests, a todo-only file, console writes of several kinds, a snapshot mismatch, a file that fails to collect) through each built-in with and without a terminal (`src/__goldens__/<name>.{plain,tty}.txt`; `json`, `junit` and `github-actions` take no terminal option and have one golden each, which both modes must equal). They pin Provino's own output and are rewritten with `PROVINO_UPDATE_GOLDENS=1`, never edited. **The claims about Jest's text are tested elsewhere, against recordings**: `provino`'s `test/reporters.test.ts` holds `provino jest` to the lines Jest 30.5.2 printed (`cli/report-default`, `report-verbose`, `report-silent`).
