# @provino/reporters

The reporter bus and the built-in reporters (coordinator side; imports `@provino/types` and Node builtins only): the text ones (`default`, `verbose`, `dot`, `agent`), `json` (`normalized-json` is the same reporter), `junit` and `github-actions` (T9.7, B21c). It reads the `report` policy slice, and only through each reporter's `report` option.

## The bus

- Reporters get an event in registration order, each handler awaited before the next. **Events are delivered one at a time** in the order `emit` was called (an internal promise chain), so no reporter ever runs two handlers at once, and a slow reporter slows whoever emits (the workers, through the pack window). A reporter must not `await` the bus from a handler: it would wait on itself.
- A handler that throws or rejects never fails `emit`. The error is recorded and sent to every *other* reporter as `error(err, 'reporter')` **right after that handler fails, before the remaining reporters get the event**; one that throws on *that* is recorded but not announced again. `failures()` is the recorded errors in order, then each reporter's `lastError()` as of the call; the coordinator turns a non-empty list into a failed run.
- So a reporter registered *after* a failing one sees the failure before the event, and one registered *before* it sees the failure after. A reporter that must record a failure at `run:end` (normalized-json) has to be registered last; `provino` does that.
- A reporter added during an `emit` first sees the next event.

## The text reporters (`default`, `verbose`, `agent`, `dot`)

One engine (`createTextReporter`), four modes. State lives in the closure and `run:start` resets it. Options (`TextReporterOptions`): `stream`, `report`, and `colour`, `live`, `columns`, `silent`, `noStackTrace`, `expand`, none on by default; `provino` fills them from `detectOutput` and the Jest flags.

- **The header is Jest's** (recorded: `cli/report-default`): `PASS ./a.test.ts` with `./` before a file in the project's own directory (`src/a.test.ts` stays), no timing unless the file took over 5 s (`PASS ./slow.test.ts (7.234 s)`, Jest's `slowTestThreshold` default; the config key is not read), a project's `displayName` before the path (`PASS server ./a.test.ts`, B17d), and **no line for a file whose every test is skipped**. A file with a `todo` test is `PASS` whatever `FileResult.state` says (DV50, settled in B21c: the orchestrator calls it `skip`, Jest calls it passed), and the totals count it as passed. With `colour`, `PASS`/`FAIL`/`RUNS` are inverse bold badges (` PASS `), the counts have Jest's colours.
- **Failures:** a failed test's title (the policy's bullet and separator) with its errors, kept from `task:end` until `file:end`; so are suites that end `fail` with errors of their own (an `afterAll` that threw, under `hooks.afterAllError: 'fail-suite'`), titled with the suite's name path (built from that file's `file:collected` tree only when the suite failed). A file's own errors (a collection error, a worker crash) print under "Test suite failed to run", or "Errors outside the tests" when tests failed too. An error prints its message (`Name:` in front unless it is `Error` or the message already starts with it), the stack's `at` frames minus `node:` and `node_modules` ones (Jest's `removeInternalStackEntries`; none at all under `noStackTrace`), then its `cause` and aggregated `errors` nested (three levels). The message is Provino's own text, not claimed to be Jest's: Provino's frames differ.
- **Console** (`console` events): kept per file until `file:end`, printed under the header as Jest's block: `  ● Console`, then `    console.log`, the message six deep, a blank line. A direct stream write is `process.stdout`/`process.stderr`. `warn` is yellow, `error` red. The worker captures no origin yet (`origin: null`), so Jest's `at Object.log (file:2:11)` line is missing (a divergence); one that is given prints after a blank line. `silent` prints none; `agent` and `dot` print none.
- **`verbose`:** as `default`, with the file's tests listed under the header (`verboseList`, recorded in `cli/report-verbose`): a suite's own tests first, then its inner suites, two spaces a level, `✓ ✕ ○ ✎`, `(3 ms)` after a test that took a whole millisecond, skipped and todo tests after the others as `skipped <title>`/`todo <title>` (`expand`: declaration order, plain titles), a blank line after the list. The console blocks come **before** the header, two spaces in, as Jest prints them live. A test that never ended and a suite with none that did are not listed.
- **`agent`:** only failed files (header and failures) and the totals; nothing for a pass, no console, no live block.
- **`dot`:** `.` passed, `F` failed, `-` skipped or todo as each test ends, wrapped at `columns` (a width that is not at least 1, as a stream with `columns: 0` reports, is 80); then a blank line, the failed files as `agent` prints them, and the totals. An `error` event during the run ends the row of dots first and prints its block under a blank line.
- **The live block** (`live`: `detectOutput` says a terminal that is not CI, not dumb, not an agent's; never in `agent`, and never in `dot`, whose row of dots the redraw would erase): `RUNS ./path` for up to four running files and `... and N more`, redrawn with `ESC[nF ESC[0J` (up n lines, erase down) as files start and end and before any text is written above it, erased at `run:end`. A name is cut to the width.
- **The summary is Jest's `getSummary`** (B21a): a count of zero is left out (`Test Suites: 1 failed, 1 total`; the `total` stays), and the suites read `N of M total` whenever the suites that ran (failed plus passed, so not a skipped file) differ from the files `run:start` announced: a run that bailed (`1 of 3 total`) and a run with a skipped file (`1 skipped, 1 passed, 1 of 2 total`), both recorded from Jest (`cli/bail-one`, `cli/skipped-file`, `cli/skipped-file-alone`). Then unhandled errors from `RunSummary`, the obsolete snapshots by file (`obsoleteBlock`), `Test Suites:`, `Tests:`, Jest's `Snapshots:` line (`snapshotLine`: zero parts left out except `total`; absent when no snapshot was checked, written or obsolete), `Time:` (`RunSummary.durationMs`; the reporter has no clock). Not printed: Jest's `Ran all test suites.` line and its per-file snapshot lines (` › 1 snapshot failed.`) and `Snapshot Summary` block (T11.9). Counts come from `test-end` events; a test that never ended isn't counted. After the summary, `RunSummary.openHandles` (when there) prints as Jest's report (`openHandlesText`: the count, each handle's `●  <kinds>`, its code frame indented 4 and its frames 6). **The wording says "Jest" for every dialect** (DV48): there is no policy key for it until T11.16 has a Vitest reporter text to record.
- Jest turns `--verbose` on when exactly one test file runs (unless `--silent` or `verbose: false`); Provino does not, so a one-file `provino jest a.test.ts` lists no tests without `--verbose` (a divergence).

## `detectOutput` and the environment

`detectOutput({ env, stream, ci, colour })` is a pure function (callers and tests pass the environment and the stream). `colour`: `FORCE_COLOR` (anything but `0`/`false`) is on and wins over `NO_COLOR`; a non-empty `NO_COLOR` is off; otherwise a terminal that is not `TERM=dumb` and not an agent's (escape sequences are noise to what an agent reads). **CI alone does not colour** (Jest's picocolors does, DV47). `live`: terminal, not dumb, not `ci`, no agent. `agent`: `AI_AGENT` (its value names the agent) or one of `AGENT_VARIABLES` (std-env 4.3's `detectAgent`: `CLAUDECODE`, `CLAUDE_CODE`, `CURSOR_AGENT`, `CODEX_SANDBOX`, `CODEX_THREAD_ID`, `GEMINI_CLI`, `COPILOT_AGENT`, `COPILOT_CLI`, `AUGMENT_AGENT`, `GOOSE_PROVIDER`, `JUNIE_DATA`, `JUNIE_SHIM_PATH`, `OPENCODE`, `REPL_ID`) set to something that is not empty, `0` or `false`, plus the three patterns (`PATH` has `.pi/agent`, `EDITOR` has `devin`, `TERM_PROGRAM` is `kiro` without a terminal). Choosing reporters from it (`agent` for an agent, `github-actions` added on GitHub Actions) is `provino`'s `reportersFor`, not this package's.

## `junit`, `github-actions` and `json`

- **`junitReporter`** writes one document at `run:end`, to `outputFile` (atomically) or `stream`: `<testsuites name tests failures errors time>`, a `<testsuite>` per file (`name` the path with the project before it, `file`, `tests failures errors skipped time timestamp`), a `<testcase name classname time>` per test (`classname` the file's path, `name` the titles joined by the policy's separator; a failed test has `<failure message type>` with the errors as text, a skipped or todo one `<skipped message>`, a test that never ended `<skipped message="not run">`, its console `<system-out>`/`<system-err>`). A file's own errors (it did not run, a worker died, an `afterAll` threw) are an `<error>` on a testcase of their own; errors outside any file are a suite of their own. Text is cleaned (ANSI and the characters XML 1.0 forbids dropped). **The output is validated against `vendor/junit-10.xsd`** with `xmllint --noout --schema` in `junit/reporter.test.ts`, and a mutated document is refused, so the check is real. The testcase has no `file` or `line` attribute there (the schema has none).
- **`githubActionsReporter`** prints `::error file=,line=,col=,title=::message` per failed test as its file ends, per file that failed to run, and for `error` events and run-level unhandled errors (no file). The location is the error's own `location`, else the first stack frame that is not Node's or a library's, else the test's, else the file alone; paths are relative to `workspace` (`GITHUB_WORKSPACE`) when given. Data and properties are escaped as `@actions/core` does.
- **`jsonReporter`** is `normalizedJsonReporter` with the name `json`.

## The normalized-json reporter

- Identity is the file path, `TestTask.fullName` and `dupIndex`. Tests are listed in declaration order by walking the tree from the file node, since `file-collect-end.tasks` is only "parents before children". A test collected but never ended (or ended `queued`/`running`) is `notRun` with no assertion count or duration.
- A file with `workerExit`, or one that failed with no tests collected, is `crashed`; otherwise `failed`/`skipped`/`passed` from `FileResult.state`. `fileError` is the file's own errors, the errors of its failed suites (`suite-end` with `state: 'fail'`) and the unhandled ones charged to it (several are joined). An unhandled error tied to a file is added to that file (and fails a passing one); one tied to no file, and every `error` event, is a `runErrors` entry. One charged to a test of the file (`ownerId` is a collected test: Jest's `errors.lateErrors: 'fail-owner'`, T5.11) is that test's failure instead: the test is `failed` with the error appended to its own, and its file `failed`, with no `fileError`. The default reporter prints it under that test and moves it from passed to failed in the tally.
- `success` is false for a failed or crashed file, a run error, or a run whose `reason` isn't `passed` (an `interrupted` one, or one the orchestrator failed on its snapshots with every file green). `snapshots` is `RunSummary.snapshots`' totals and the `.snap` files the run left, each with the sha256 of its bytes and its path POSIX and relative to `run:start`'s `root` (`normalizeSnapshots`; a file that can't be read is left out); `trace` (T12.7) is left out. `expectedToFail` and `location` are filled the way the harness's Jest converter fills them. `retries` counts `test:attempt-end` events with `willRetry` (real retries only: `TaskResult.attempts` also counts repeats); without any attempt events it falls back to `attempts - 1`, unless the test repeated, when it is left out.
- **Console** (B15): every `console` bus event is kept in the file's record and written split on `\n` (a trailing newline ends the last line, so `console.log('')` is one empty line), with `stream` and `level` (none for a direct stream write). A write whose `taskId` is one of the file's tests goes on that test, its each-hooks included; a suite's or the file's `beforeAll`/`afterAll`, the top level and a write outside any task go on the file. A file or test that wrote nothing has no `console` key. The text is as the worker captured it: the harness's `convertProvino` normalizes it.
- `unhandledErrors` (`'fail-run'` default, or `'ignore'`) mirrors the orchestrator's policy: under `ignore` unhandled errors are still recorded (`fileError`, `runErrors`) but fail neither a passing file nor `success`. `error` events (including `reporter` ones) always count. `provino` passes the policy's value.
- `outputFile` is written to `<path>.<pid>.<random>.tmp` beside it and renamed over it, so concurrent runs and a kill mid-write never leave corrupt JSON; a failed write removes the temp file.
- `env.ci` is the `ci` option when given (over `env.ci` of an `env` option too): `provino`'s `run()` passes the ci it resolved, so the file agrees with the run. Only without one does the reporter read `CI` itself, by the same rule.
- `startedAt` is the wall clock at `run:start` (`now`, default `Date.now`). A failed write throws out of `run:end`, so the bus records it and the run fails.
- The tests assert the JSON's shape directly: `parseNormalizedRun` lives in `@provino/harness`, which this package's manifest node may not import. B11's bench check runs it on real output.

## Goldens

`builtins.test.ts` plays the fixture run (`FIXTURE_FILES` in `internal/test-support.ts`: a pass with nested describes, a failure, a skipped and a todo test, a file of only skipped tests, a todo-only file, console writes of several kinds, a snapshot mismatch, a file that fails to collect) through each built-in with and without a terminal (`src/__goldens__/<name>.{plain,tty}.txt`; `json`, `junit` and `github-actions` take no terminal option and have one golden each, which both modes must equal). They pin Provino's own output and are rewritten with `PROVINO_UPDATE_GOLDENS=1`, never edited. **The claims about Jest's text are tested elsewhere, against recordings**: `provino`'s `test/reporters.test.ts` holds `provino jest` to the lines Jest 30.5.2 printed (`cli/report-default`, `report-verbose`, `report-silent`).
