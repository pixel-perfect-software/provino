# @provino/loader

The module loader (Track 2): a two-phase module-runner engine. One `Loader` per worker; one `FileRegistry` per test file. It runs in **both** halves (manifest `runsIn: both`, U5, D74): the worker's engine, and a coordinator mode that imports a global setup module (see below). It never imports `@provino/mock`, a worker package; the worker passes the module-mock registry in. The contract (`Loader`, `FileRegistry`, `LoaderOptions`, `CreateLoader`, `ModuleMockRegistry`) lives in `@provino/types`. The spec is Track 2 R1–R2 and F3; B06's notes are in `docs/plan/bundles/B06.md`, B13c's (mocks in the loader, T2.5 + T4.8) in `docs/plan/bundles/B13c.md`.

## Two halves

- **Worker-wide: `src/internal/records.ts`.** Each user module has one `ModuleRecord` per worker:
  - transformed once: the `ModuleTransformer` (the pipeline, with the dialect's hoist policy), then `toModuleRunner` from `@provino/transform` for files with ESM syntax, or with `import()` and no other module syntax (format `unknown`, which a CommonJS `vm` script can't run). A file that calls `require` or uses `module`/`exports` is `cjs`, `import()` or not, and keeps the CommonJS wrapper;
  - its static deps resolved once; one that doesn't resolve is a `missing` target, and a user module that doesn't transform (a `.css` file) a `failed` one, each thrown only when its edge runs and decides on the real module (B13c Gap 7; so a factory for `./styles.css` never transforms it);
  - compiled once per mode with `vm.runInThisContext`, with `filename` set to the real path.

  `linkAsync`/`linkSync` walk the static graph. A record's `lateDeps` (D38) are never linked. Externals (anything under `node_modules` that `inline` doesn't match, plus addons and builtins) are shared by the worker: under `interopDefault: 'node'` the async path preloads them with native `import()` (Node's namespaces); under `babel` nothing is preloaded, and an edge `require`s the external when it runs, as Jest's CommonJS output does, so a mocked package never loads. `asyncGraph` marks top-level-await subgraphs and `lateGraph` the subgraphs that reach a module with late deps, both as one fixed point over cycles. `markAsyncGraphs` scans every record in the worker, so it runs only while `Records.asyncGraphsStale` is set: a new record, a record linked and every `resolved` write (through `setResolved`) set it, and the scan clears it.
- **Per file: `src/internal/registry.ts`.** A stack of instance maps; the top one is live, and `isolateModules` pushes a fresh one. Evaluation calls a record's compiled wrapper with fresh linkers, so module state is per registry while compiled code is shared. The registry carries the running file's `FileContext` (`{ mocks, scope }`); under `none` the registry is shared and each file sets its own.
  - `resetModules` empties every layer in place and keeps the stack's depth, so a reset inside `isolateModules` leaves the registry (under `none`, the worker's shared one) usable.
  - `isolate`/`isolateAsync` remove the map they pushed, by identity, not whatever is on top: overlapping async isolates each drop only their own map. The loader's `FileRegistry.isolateModules` also opens the module-mock registry's overlay, which refuses nesting with the dialect's `nested-isolation` text.

**Coordinator mode (U5, `src/coordinator.ts`).** `createCoordinatorLoader(root, config, policy)` is `createProjectLoader` with the mock side taken away and one tier, `none`: `config.hoist` and `moduleScope` are cleared (no mock registry for a hoisted call to reach, no `jest` binding: a module that names `jest` sees the global of that name, which a coordinator has none), `mocksReachShared` is off (no lexer, no graph), and every file is imported at tier `none`, so a setup and its teardown share module state. `import(file)` resolves with the module's exports as an `import` sees them under `interopDefault`: for `module.exports = fn` and for a compiled `export default` alike, `default` is the function (the orchestrator also unwraps a `__esModule` default, for `node` interop). **It installs nothing process-wide**: the engine compiles with `vm` and links itself, so there is no `module.registerHooks` or `require.extensions` hook, and the coordinator's own imports resolve as before (`coordinator.test.ts` pins the extension table and counts calls to `module.registerHooks` and `module.register`, zero). A Jest transformer (`config.transform`) loads in the coordinator's process, from its own path. It reports nothing of what a module loaded (`FileRegistry.loadedModules()` is the worker's).

`FileRegistry.loadedModules()` is **per file** (the `deps` event reads it): under `registry` it is the file's own instances; under `none`, where the registry outlives the file and a module an earlier file evaluated is found, not evaluated again, `Registry.#touched` counts the modules the file asked for (the runner's own loads, the actual paths, and each new instance `#newInstance` makes; an instance found by an edge isn't added again, the walk below reaches it) and `loadedByFile()` follows their dependency edges to the loaded modules they reach (a module is loaded when some map of the stack holds it: no copy of the registry is made per file). **The edges are read, not resolved:** the walk takes the targets a record's `resolved` map already holds (every static dep as `linkDep` linked it, and any specifier a `require` resolved since), so the walk, which runs once per file over every module the file reaches, asks the resolver for nothing (`reading a file’s closure resolves nothing…` counts the resolver's calls). `userEdgesOf`, which does resolve, is the graph walk's and `#maybeInline`'s, for a module that may not be linked. A late dep (D38) is never in `resolved`; it comes through the dynamic loads below. Over-approximate for a CommonJS module (its `require` calls as the scan sees them). **A module's dynamic loads are part of its edges:** while a file is counted, `requireFrom`, `importFrom` (a runtime `import()` and the async late import) and the sync late import note, per importing module, the user module each one loaded (`Registry.#dynamicLoads`; a `require` whose target the record had already linked isn't noted, the walk follows it), so a `require(variable)` or a runtime `import()` an earlier file ran is still followed when a later file reaches that module without evaluating it again. It is kept per importer, not per evaluation: a lazy `import()` that an earlier file's code ran later (from a function it called) counts for the next file that reaches the importer too, an over-approximation like the static scan's. **Known over-approximation, not fixed:** `#touched` is one set for the shared registry, not one per file, so a load a file left in flight (an `import()` it did not await, still linking when its file ended) adds its module to whichever file is being counted when the load evaluates, the next one when it has begun. Telling the files apart would need the file in each load's async context (an `AsyncLocalStorage` entered by every entry point), and a test body's `import()` and a module's closures run outside any entry point and outlive their file under `none` (the closure a module gets at evaluation serves every later file), so it is a change to every edge, not a small one. The cost is an extra dep on the next file, never a missing one. `loader.test.ts` pins both tiers and both dynamic forms.

`src/loader.ts` holds `createLoader` and the tiers (`tierFor` is `src/tier.ts`'s). `registry` creates a new `Registry` per file; `none` reuses one per loader.

`src/project.ts` holds `createProjectLoader(root, config, policy.module)`: the worker's way in. It builds the resolver and the transform pipeline from a clone-safe `SerializedLoaderConfig` (the worker entry may not import either; `config.hoist` is the dialect's hoist policy, by value), loads the config's mappers by `ModuleRef` (so it is async), and calls `createLoader` with the runner engine and `config.moduleScope`'s names. `config.cacheDir` (set by the coordinator, absent under `--no-cache`) turns the transform cache on: the pipeline reads a file's record before any work and writes it after (T3.6, `packages/transform/CLAUDE.md`), so a hit restores `staticMocks` and `lateDeps` with the code. `config.transform` (T3.8) loads the project's Jest transformers there (`createJestHost`, by path, in the worker) and hands them to the pipeline: a file a transform matches goes through its transformer, every other file through Oxc (`transformers.test.ts`).

- **`tsconfig`:** `'auto'` and `false` pass through. Any other string is a file path, resolved against `root` (never the process cwd) for both the resolver and the pipeline, and it must be a file: otherwise `createProjectLoader` rejects with `LOADER_TSCONFIG_NOT_FOUND`, naming the resolved path.
- **Resolver keys (T3.3, B17c):** `config.aliases` (Jest's `moduleNameMapper`, regex sources in order) become one `createNameMapper` that runs before the loaded mapper factories; `moduleDirectories`, `modulePaths` (the retry after a miss) and `resolver` (a `ModuleRef`, loaded by the behaviour loader, a function or `{ sync }`, called with Jest's `(path, { basedir, conditions, defaultResolver, extensions, moduleDirectory, paths, rootDir })`) go to `createResolver`. A mapper rule that matches but doesn't resolve is a `not-found` result carrying `mappedBy`, `tried` and `declared` (the targets before `$n`); the loader raises the text `ModulePolicy.mapperMiss` gives (a behaviour, loaded by `createProjectLoader` into `LoaderOptions.formatMapperMiss`, handed `{ specifier, rule, declared, tried, resolver }` with `resolver` from `LoaderOptions.resolverName`; Jest's is `formatMapperMiss` in `dialect-jest/runtime`), else `module-not-found`. Recorded: `resolve/mapper-miss`. `ModuleScope.mappable` names the served modules a matching rule takes over (`mapperTakes`, checked in `resolveOrMissing` and `#served`).
- **Mappers:** each factory's result must be an object with a string `id` and a `map` function. A factory that throws (the error is the `cause`) or returns anything else rejects with `LOADER_INVALID_MAPPER`, naming `loader.mappers[<i>]`. Factories are called synchronously, as `ModuleMapperFactory` says.

`FileRegistry.invalidate(specifier, parent?)` drops the live instance of the user module the specifier resolves to, in the top map of an `isolateModules` stack. It resolves the specifier as an `import` and as a `require` and drops both ids, since a package's `exports` can map the two to different files and either may be the loaded one (a kind that doesn't resolve is skipped). Under `none` the registry is shared, so it reaches every file of the worker.

## Mocks (T2.5 + T4.8, B13c)

- **The worker builds the module-mock registry, not the loader** (Gap 1): it also needs the mock slice and the file's mock registry, which the loader never reads (non-negotiable 3). `FileRegistryOptions.moduleMocks` is a factory the loader calls once, with `{ loadActual, resolver, conditions }`. Without one, nothing is mocked and `registerMock`/`unregisterMock` throw `LOADER_NO_MODULE_MOCKS`. `FileRegistry.dispose` disposes it too.
- **Every edge decides.** A static import (`#importEdge`), a `require` (`requireFrom`, with the record's linked targets), an `import()` (`importFrom`) and a late import resolve, then ask `decide(id, importer, 'esm' | 'cjs' | 'builtin', specifier)`; a `missing` target asks `decideUnresolved` and throws its `ModuleNotFoundError` only if nothing stands in. A mocked edge gets `materialize`'s value: under `factoryShape: 'module-value'` an `import` sees it through the CommonJS interop; under `awaitFactory` a Promise is a result to wait for (`Pending`), which a sync edge refuses with `ERR_REQUIRE_ASYNC_MODULE`. Each wrapper passes its mode to its edges, so a plain wrapper never binds a Promise; an ES module loaded by `import` takes the async wrapper when its graph awaits (`asyncGraph`), reaches late deps (`lateGraph`), or may meet a pending mock (`awaitFactory` with mocks in play). The runner's own loads (`import`/`require` with no `parent`: setup files and the test file) never ask about the module itself.
- **The actual paths** (`requireActual`, `importActual`, and the registry's `loadActual`, which follows `ModulePolicy.actual`) bypass the mock of the module they name only; its own imports still decide. An ES module comes as its exports' view. `loadActual(id, importer, { scratch: true })` (automock) evaluates in a scratch instance map dropped afterwards, as Jest's `_generateMock` does; the registry swaps its mock values for the synchronous part. The scratch map is carried in an `AsyncLocalStorage` (`#inScratch`), so a load running beside an async scratch load (`Promise.all`) never lands in it, and `#actualAsync` keeps the instance it evaluated rather than looking it up after an `await`. Two automocked modules that import each other end: the module-mock registry serves an empty automock on re-entry, as Jest does.
- **A CommonJS module whose evaluation threw is forgotten,** as in Node and Jest, so the next `require` (after a `doMock`, say) runs it again. An ES module keeps its error.
- **Late imports (D38).** The hoister writes `await __provino_import__('./a')`; the wrapper passes `__provino_import__`. A record with late deps compiles in both modes as needed: an `import` that reaches it, directly or through static imports (`lateGraph`), evaluates async (the `await` stays, so a late dependency with top-level await works); `require` of it evaluates sync with the `await` stripped, so `require()` of an ESM helper that hoists works as in Jest, and a late dependency with top-level await then throws `ERR_REQUIRE_ASYNC_MODULE` ("… can't be loaded synchronously").


## Mock-aware auto-inlining (T2.6, B13d)

A shared external (a node_modules file) loads natively, so its own `require`s never meet the mock registry. When `ModulePolicy.mocksReachShared` is set (Jest and neutral `true`, Vitest `false`; recorded by `mod-shared-dep` and `mod-shared-dep-root`), an edge that reaches an external asks `Registry.#maybeInline` whether the external's graph closure holds an edge the file's mocks take. If so the external is a user module for that file (a `user` target, a record with role `dependency`, so no hoisting, and `CompiledModuleEvent.thirdParty`), and its own edges decide in turn.

- **`decide()` is the authority** (`src/internal/inline.ts`, `mockedReach`): each distinct edge of the closure (its specifier as written, its resolved id, `esm`/`cjs`/`builtin`) is put to `decide`; an edge that didn't resolve to `decideUnresolved` (a virtual mock). `decide` has no side effect that matters here (it remembers a specifier for an id, and under automock-all adds a deep unmock's imports, each of which the real edge does a moment later).
- **The walk goes through user modules.** A closure edge that leaves `node_modules` (a workspace package linked into it resolves to its real path) is followed through the loader's own record of that module (`userEdgesOf` in `records.ts`: its deps resolved as an edge would), and back into any `node_modules` file those reach, so a package that requires a workspace package that requires a mocked module is inlined, as under Jest (`a package reaches a mock through a workspace package…` pins it, on a pnpm-style tree). The graph itself stays types-and-resolver only.
- **A verdict is kept** per mock registry until its `generation()` changes (a registration, an unmock, `setAutomock`, a `resetModules` that clears them): `resetModules` and `isolateModules` don't decide again. A negative verdict holds for every node_modules file the walk covered. The closure's deduplicated edges are computed once per worker (`graph.edgesOf`).
- **No mock, no scan.** The gate is `ModuleMockRegistry.active()` (a registration, automock-all, or root mocks to apply: `decide`'s fast path, inverted). With it `false` the graph isn't even built. `with no mock, nothing is scanned or cached` pins it.
- **A served module keeps its instance** (Gap 3): `Registry.#memory` holds, per instance map, whether each external was served shared (`false`) or inlined (`true`); a `doMock` after the first load changes nothing, `resetModules` clears every layer's memory, `isolateModules` decides afresh in its own layer. Under `none` the shared registry outlives the file, so `FileRegistry.dispose` calls `dropInlined()`: inlined instances and the memory go, and the next file sees the shared module.
- **What it covers:** every edge kind (static import, `require`, `import()`, late import) and the actual paths (`requireActual`'s real module is inlined too, so its own imports stay mocked). An inlined module not linked ahead is linked on the spot (`#linkNow`). Addons never inline. A node_modules path matching `LoaderOptions.inline` is an ordinary user module (role `source`), as before.
- **Warnings** (`LoaderOptions.onWarning`, default `process.emitWarning` with the code, debug level dropped): `PROVINO_INLINE_BUDGET` once per mocked id per worker when more than `inlineBudget` (400) modules inline for it in a file (it still inlines); `PROVINO_INLINE_DYNAMIC` (debug) when a shared closure holds a computed `require` while mocks are active, an edge the graph can't see. Inside an inlined module every `require` is an edge we see, so dynamic ones are checked at run time. The worker doesn't route either to reporters yet (Track 9).
- **`LeakReport.inlinedForMocks`** is what the file inlined (`FileRegistry.dispose()`'s report).
- **The lexer:** `createProjectLoader` awaits `initLexer()` (`init()` of es-module-lexer's wasm build) once per worker when the policy asks for inlining; a loader made directly (tests) compiles it on the first scan. `RegisterMockOptions.hoisted` is not read: the lexer is ready before a file loads, so there is no warm-up to do (B13d Gap 4 allowed this).
- **Not covered:** Jest's transitive node_modules rule under automock-all (`applyTransitive`, not built in `@provino/mock`).

## Tier selection (`src/tier.ts`, T2.11)

`tierFor(testFile, { configured, docblock?, learned? })` -> `{ tier, source, warnings }`, also `Loader.tierFor`. The project's tier is the floor; the file's `@provino-isolate <none|registry|realm|process>` pragma and a tier an earlier run learned (the results cache's `FileHistory.tier`) can only raise it. A request below the floor changes nothing and says nothing; a value that is no tier (`''`, `Registry`, `jail`) is a warning and the file keeps what the other sources gave; a repeated pragma counts each value; `source` is `config`, `docblock` or `learned` (the first of them that names the chosen tier). `process` is the coordinator's: the orchestrator turns it into a worker of its own through `WorkerKey.isolation` (`packages/orchestrator/CLAUDE.md`). The loader's own `createFileRegistry` still never sees `process`. `isolatePragmaOf(source)` and `readIsolatePragma(path)` are the coordinator's narrow docblock reader (jest-docblock's grammar for one pragma: the first comment only, `*` prefixes, `//` dropped from the value; the first 4 KiB, all of the file only when the comment is open there); the worker reads the full docblock for the environment (`@jest-environment`), and no `@jest-environment` value maps to a tier. `tier.test.ts` holds the raise, refuse-to-lower and unknown-value cases.

## The graph (`@provino/loader/graph`, D52)

`src/graph/`: its own subpath entry and manifest node (layer 2, `runsIn: both`; it may import `@provino/types` and `es-module-lexer`, never the loader's root), so Track 9's affected-test selection can use it in the coordinator. `scanSource` (`scan.ts`: `es-module-lexer` for ES syntax, one pass over `require`/`module.require` for CommonJS, over-approximate; a computed or aliased `require`, `createRequire` and a file the lexer rejects are `dynamic`), `buildThirdPartyGraph` (`build.ts`: lazy, entries added with `add`, edges resolved with the worker's resolver, `reachable(path)` the closure, `edgesOf(path)` its deduplicated edges, `save()`; a file that couldn't be read or an edge the resolver threw on is `dynamic` and never saved), `importersOf` (`query.ts`), `cache.ts` (`<cacheDir>/graph/<key>.json`; the key hashes the lockfile's hash, which the loader takes from `@provino/transform`'s `lockfileHash` and passes as `GraphOptions.lockfileHash`, the install marker's size and mtime, the format, the lexer's version and the resolver's fingerprint and conditions; no lockfile hash means memory only; each node carries its file's mtime and size, checked with one `stat` the first time a walk visits it in a worker, and rescanned on a mismatch; a node is built from its stored form on that first visit; read once, written once per worker, from the loader's `dispose`, with a nonce-named temp file and a rename, merged with the copy on disk in stored form; a corrupt file is rebuilt). `conditions.ts` holds the one `conditionsOf` default. `pnpm bench:loader graph` holds it to 300 ms cold and 20 ms warm over a 1,246-file corpus (`local`).

## Source-mapped stacks (`src/stacks.ts`)

`installSourceMappedStacks(loader)` (the worker's runner calls it once, after `createProjectLoader`, and its `stop` calls the uninstall it returns) sets an `Error.prepareStackTrace` that maps each frame in a module the loader compiled through `getSourceMap(path)` (the record's map composed back to the source: a Jest transformer's or Oxc's, then the hoister's, then the module-runner edits), then hands the frames to the formatter it found (Node's own, so a coded Node error keeps its `[CODE]` header). A frame keeps its file and V8's function name; its line and column move only when the map has a segment on the frame's own line at or before its column (`findEntry` of `node:module`'s `SourceMap`, held to the same line as `source-map-support` and trace-mapping do: no new dependency). Any other frame, and any failure while mapping, stays as V8 gave it. Maps are decoded once each, on the first frame that needs one, so a run pays only for the files whose stacks are read (core reads each test's location at registration, which includes the test file). The formatter also carries its mapper under the registered symbol `provino.mapCallSites` (`MAP_CALL_SITES`), which the coordinator's `--detectOpenHandles` uses on the structured call sites it captures (it swaps the formatter out to get them, in the process an inline worker runs in). Not mapped: `eval` frames, and the function name (Jest names a frame after the map's `name` at its position, `at toBe (…)`; Provino keeps V8's, `at Object.<anonymous> (…)`). `stacks.test.ts` holds a frame below a multi-line import and one on line 1 to the file's positions; `provino`'s `stack-frames.test.ts` holds `provino jest` to Jest 30.5.2's (`cli/stack-frames-after-imports`) under Oxc, `@swc/jest` and babel-jest.

## Interop (`src/internal/interop.ts`, Gap 3)

Pure functions, by `ModulePolicy.interopDefault`, held to B13b's fake loader's rules by `interop.test.ts` (the mod corpus ran against them before the fake went):

- `esmExports`: an ES module's exports object. `babel`: a plain object with a hidden `__esModule`; `node`: a null-prototype `Module` namespace.
- `cjsNamespace(value, interop, cache)`: a CommonJS value (or a module-value mock) seen through `import`. `babel`: Babel's wildcard (a value with `__esModule` is its own namespace; otherwise `default` first, then the own enumerable keys, copied as they stand); `node`: every key sorted with `default` among them, `Module` tag. A `Module` namespace stays as it is. Built once per value (the registry's cache), except from a CommonJS module still evaluating.
- `actualView`: getters over the live exports; `babel` hides `__esModule` and sorts the names, `node` is a `Module` view in source order.

## Scope bindings (Gaps 2 and 5)

`LoaderOptions.moduleScope.names` (the dialect's, through `config`: Jest's `jest`) and, for ES modules under `injectCjsGlobals`, `require`, `__filename` and `__dirname`. A word scan at the first compile (`scopeOf`) keeps the names the source uses; a module that names none gets no outer function and pays nothing. A module that names one is compiled as `(function (jest, …) { return function (<wrapper params>) { … } })`, so its own `const require = …` shadows the binding instead of clashing with a parameter. The values come from `FileRegistryOptions.moduleScope(from)`, once per module evaluation; a name with no value falls back to the global of that name.

## Message codes (`src/internal/messages.ts`, Gap 4)

Read from `ModulePolicy.messages`, like the module-mock registry's. `transform-failed` (`{file}`, `{where}`, `{message}`; a code frame follows after a blank line; neutral `{file}{where}: {message}`, Jest `{file}: {message}`), `module-not-found` (`{specifier}`, `{from}` relative to the root, `{importer}`; Jest's is jest-resolve's), `unresolved-mock-import` (no neutral text; Vitest's profile appends ` imported from {importer}` when the test file's load fails on `unresolved-relative-mock`; an import from inside a test isn't wrapped). A not-found error is a `ModuleNotFoundError`, whose `name` stays `Error` (Node's and jest-resolve's are), code `MODULE_NOT_FOUND` for a `require` and `ERR_MODULE_NOT_FOUND` for an `import`.

## The wrapper shape (the module-runner transform's output: oxc's shape, our own transform)

- **Imports** become `const __vite_ssr_import_N__ = await __vite_ssr_import__('./x', { importedNames })`. Uses become `__vite_ssr_import_N__.x`, which stays live.
- **Exports** become getters on `__vite_ssr_exports__`, hoisted above the imports, so cycles see live bindings.
- **`export *`** becomes `__vite_ssr_exportAll__(ns)`: one argument, bound to the module's own exports.
- **Other rewrites:** `import()` becomes `__vite_ssr_dynamic_import__`, and `import.meta` becomes `__vite_ssr_import_meta__`. The hoister's rewritten imports are `__provino_import__` calls.
- **Positions:** the wrapper opens on the body's first line, so `compile()` passes `columnOffset: -prefix.length` and every frame, line 1 included, is a position in the body: the code the record's map starts from.
- **Sync evaluation:** the plain `function` wrapper, with `await __vite_ssr_import__(` and `await __provino_import__(` stripped. Only `asyncGraph` modules, and an `import` of a module with late deps, use the `async function` wrapper. The compile listener fires once per wrapper compiled.
- **CJS** user files use Node's `(exports, require, module, __filename, __dirname)` wrapper. `require()` of an `asyncGraph` ESM module throws `ERR_REQUIRE_ASYNC_MODULE`. A CJS file that calls `import()` takes the module-runner form (for CommonJS that is the source with `import()` rewritten to `__vite_ssr_dynamic_import__`) and its wrapper a sixth parameter of that name, bound by the registry that evaluates it (`ModuleRecord.dynamicImport`): a `vm` script has no import callback, and one script serves every registry in the worker, so a bare `import()` would fail with `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING` (T2.3 found it). A CJS module with no `import()` keeps the five-parameter wrapper.
- **`require.cache` is Node's own cache** (`native.cache`), which the registry never reads or writes: a module the registry loaded is not an entry, and `delete require.cache[id]` does not make the next `require` evaluate it again (DV79, pinned by `require-cache-user-module`). Node's is a live view of what `require` loaded, and Jest's is a read-only Proxy over its registry where delete and assign do nothing; which one a dialect gets is a `ModulePolicy` key (D7), proposed as a decision, not built here. The `module` object a CJS wrapper gets has only `exports`.
- **`import.meta`** has no prototype, as Node's; `import.meta.resolve` answers a relative, absolute or `file:` specifier the resolver does not find with the URL it names (Node never looks), and throws only for a package or builtin that is not found.
- **A hashbang** is legal only at the start of a script or module, and the wrapper puts the body inside a function, so `compile()` writes `//` over a body's leading `#!`, for both formats, before wrapping. The length is the same, so `wrapperColumnOffset` and the maps hold; the transform keeps the `#!` and puts its generated block after it.

## Semantics suite (T2.3, `src/semantics/`)

One fixture per Track 2 F3 row, each run through native Node and through the loader and the two observations diffed (`pnpm test --filter @provino/loader` runs it). The harness is `src/internal/test-support.ts` (the path the Biome slice rule exempts): a fixture is a tree of source strings written to a temp dir at test time (no `.js`/`.mjs`/`.cjs` is committed, D13) and an entry (`.cjs` is `require`d, else `import`ed). Native is a child process on `process.execPath`; Provino is `createLoader(...).createFileRegistry(entry, { tier: 'registry' })` in the test process. Both observe `globalThis.__trace` (an array the fixture's modules append JSON-safe values to) and the entry's awaited `result` export, or the error a load threw (`name`, `code`, `message`; `messages: false` drops the message where Node's text is not stable). Paths are normalised to `<root>`. `expectSame` asserts equality; `expectDivergence` pins what Provino does and asserts it still differs from Node, so a fix shows up as a failing test to delete. A fixture whose native result depends on the Node version (`import.meta.main`, the `module.exports` name of a CJS namespace) reads the native observation to decide.

## Gotchas

- **The module-runner step is `toModuleRunner`, in `@provino/transform` (B20).** Our own transform on `oxc-parser`; unstripped TypeScript is a per-file parse error, and no production file names oxc's deprecated `moduleRunnerTransformSync` (DECISIONS D10).
