# @provino/dialect-jest

The Jest 30.5 dialect. B08 built its `expect` part: the `ExpectPolicy` slice and the matcher table. B10 added the `Dialect` value (`jestDialect`, with `jestPolicy`) and the globals (`jestGlobals`). B14a backed every value with recorded ground truth: the evidence is in `@provino/harness`'s `src/policy-truth/claims/`, and `policy-truth.test.ts` fails when a value and its evidence disagree (a few are `pending` with an owner). B14b added the config reader, the `/node` entry (see "The config reader"). B14c added the command-line parser (T11.7, see "The command line"). Still to come: the full `jest` object and the `@jest/globals` facade (T11.10, B13, B17). Follow `.claude/rules/dialects.md` and `.claude/rules/vendored-upstream.md`.

## The command line (`./node`, B14c)

`jestCli` (`CliDialect<JestArgv>`, on `jestNodeDialect.cli`; `jestFlags` is `.flags`) turns Jest's command line into Jest's own argv and a neutral `RunRequest`. It is our rebuild of jest-cli 30.5.2's `buildArgv`, with no yargs, jest-validate or leven dependency; jest-cli is a devDependency, the oracle.

| File | Role |

| `cli-table.ts` | `JEST_CLI_OPTIONS`: the 105 `yargsOptions` of jest-cli, copied in its order with its descriptions, plus our `support` for each (`request` 16 (`--color` and `--colors` among them, B21c: `RunRequest.colour`), `config` 66 (`--filter` and `--projects` among them, B23d: the reader and `provino jest` read them from the argv; `loadJestFilter` and `jestDebugText` are in `src/node/filter.ts` and `debug.ts`) (`--verbose`, `--silent`, `--expand` and `--noStackTrace` among them, B21c, D54: `provino jest` reads them from the merged global config for its reporters; `--bail` (`--bail=2` is false in Jest 30.5.2, as `--no-bail`), `--forceExit` and `--detectOpenHandles` among them, B21a: `provino jest` reads them from the merged global config, so the request has no field for them), `accepted` 6 (`--selectProjects` and `--ignoreProjects` read by `provino jest`, D69, and `--debug`, which it prints), `warn` 3 (`--logHeapUsage`, `--notify`, `--notifyMode`), `refuse` 14) and, for a refusal or warning, its `owner` task |

| `internal/cli-oracle*.ts`, `cli-encode.ts` | The tests' oracle: one child process runs real `buildArgv` over every case (it stubs `process.exit`, as yargs calls it on a failure) |

- **Errors are Jest's text.** `check`'s messages, yargs' (`Not enough arguments following: …`, `Invalid values:`) and jest-validate's (`● Unrecognized CLI Parameter:` with the did-you-mean, the 12 deprecations, `--testPathPattern`'s "replaced by --testPathPatterns") come as a `JestCliError` (`JEST_CLI_INVALID`, `_UNRECOGNIZED`, `_DEPRECATED`) whose `message` is what Jest prints, uncoloured. Real Jest exits 1 for all of them; the caller maps the error to `orchestrator.exitCodes.usage`. `--help`, `--version`, `--get-yargs-completions` and a flag named like an `Object.prototype` member (real Jest crashes) are `JEST_CLI_UNSUPPORTED[_FORM]`. Faithful quirks are kept (`-tfoo` is `-t -f -o`; `--x=1 --x=1` counts to 2; `--bogus=1` isn't reported, as in jest-validate).
- **Nothing is silently ignored (gap 9).** A flag given with a truthy value that has no backend yet is an `error` diagnostic `JEST_CLI_UNSUPPORTED` ("--watch is not supported yet (T9.11)", by the option's long name); a flag that is read and not applied (`--logHeapUsage`, `--notify`, `--notifyMode`) is a `warning` `JEST_CLI_NOT_APPLIED` (T9.7), where `--verbose`, `--silent`, `--expand`, `--noStackTrace` and `--color(s)` now say nothing because the reporters apply them (B21c, D54); a config key given as a flag reaches the config reader through the argv and is that reader's to apply or warn about. `--json`, `--outputFile`, `--useStderr`, `--testLocationInResults` and `--collectTests` are applied (B23a); `--reporters` too.
- **`RunRequest`:** positionals and `--testPathPatterns` are `regex` file filters (positionals are `path` filters under `--runTestsByPath`), `-t` the name pattern, `-w` a count or `N%`, `-i`, `--workerThreads`, `--ci`, `--passWithNoTests`, `--cache`, `-c`, and the mode (`--showConfig`, then `--clearCache`, then `--listTests`, Jest's order). A `-w` that is neither a count nor a percentage is `JEST_CLI_INVALID`. The flags that are config keys are not in the request: `provino` passes the argv to the reader, which normalizes them (`maxWorkers`, `ci`, `testNamePattern`, `testFailureExitCode`, …).
- **Tests:** `cli.test.ts` (36 tests, four oracle children at once, about 7 s here; CI runs every package's tests together and a single child timed out at 120 s): argv equality with `buildArgv` on about 2,300 lines (154 hand-written, every option in its forms, 800 from a seeded PRNG), failure parity, the table against `yargsOptions` key by key, the goldens `cli/jest-test-path-pattern` and `cli/unknown-flag` (their kept lines equal ours), the classification, and each F5 row's request.

## Reporters, results and Jest's text (`./node`, B23a)

- `src/results/` builds Jest's `AggregatedResult`, `TestResult` and `AssertionResult` from the run's events (`build.ts`, `collect.ts`, `format-json.ts`, `failure-message.ts`); `failureTextOf(fileId)` is the file's `failureMessage` in blocks, one per failed test (its assertion formatted alone: `formatResultsErrors` joins one block per failure with `\n`) and then the file's own errors, which the text reporters print with each test's lazy values after its block. `failureDetails[i]` is a plain object whose own enumerable keys are what `--json` writes and whose non-enumerable `message`, `stack` and `name` are what a hook reads (jest-junit's `noStackTrace`). `hideProvinoFrames` drops the frames of `<repo>/packages/<name>/src|dist` (the built umbrella's `packages/provino/dist` too; decoded, since `import.meta.url` is percent-encoded and `file://` frames are not) and an install's `node_modules/provino` and `node_modules/@provino/<name>` (D104), never a test, fixture or project that sits under `packages/`. `github-actions.ts` refuses `silent: false` by name (`load.ts`).

## `@jest/globals`, the served modules and the environment adapter (B17c)

- **Served modules.** `jestDialect.moduleScope.modules` is `['@jest/globals', '@jest/expect', 'expect', 'jest-mock']`: `jestModuleScope(host)(from)` returns the `jest` binding and, as non-enumerable lazy getters, a value for each. An import of one never reaches the resolver, `moduleNameMapper` or a mock (the loader's `FileRegistry.#served`), as jest-runtime answers `@jest/globals` first. `@jest/globals` is the injected globals (`jestGlobals(host)` is memoized per host, so they are the same objects) with the module's own `jest`; the scope keeps one `jest` per `from`, so the `jest` a module's wrapper binds is the one `@jest/globals` hands it (recorded: `facade/globals-identity`). **Divergence:** real Jest 30.5 loads the *project's installed* `expect` / `@jest/expect` into its internal registry (a decoy package showed it) and fails with "Cannot find module" when none is installed; Provino serves its own facade regardless. `jest-mock` is `{ fn, spyOn, replaceProperty }`, with no Jest ground truth.
- **`globals` config.** `jestProjectToNeutral` puts it in `NeutralProject.globalValues`; the worker defines a copy on the environment's global for each file before anything else runs (`facade/globals-config`).
- **`src/runtime/jest-environment.ts` (T8.5, D44).** `jestEnvironment` runs the Jest environment class a project names (`options.module`, the project's own copy): `prepare` imports the class once per worker; `setup` builds `new Class({ globalConfig, projectConfig }, { console, docblockPragmas, testPath })`, calls `setup()`, and `populateGlobal`s its `global` onto the worker's (`@provino/env-shared`; `window`/`self`/`top`/`parent` only when the class's global has a `document`); `teardown` calls the class's, then (in a `finally`, so a class that throws still restores) restores the worker's global with `@provino/env-shared`'s `snapshotProperties` (D71, the same restore as `nodeEnvironment`, taken before the class was built): a key the file added is deleted, one a test replaced (`fetch`, `setTimeout`) is defined again, and an assignment to a closure-backed accessor (`performance`, `process`) is undone (a process singleton symbol such as graceful-fs's queue is not a leak). A `setup` that fails tears the class down and restores before rethrowing. With `processObject: 'per-file'` in the context (the dialect's `orchestrator.processObject`, recorded by the harness's `env/process-*`), `setup` also assigns the class's own `global.process` (jest-util's per-file copy, which `populateGlobal` doesn't carry over) to the worker's global, after the snapshot, so teardown puts the worker's back (`jest-environment-restore.test.ts`). `NODE_PATH` entries are the first `modulePaths` of a project, as jest-resolve searches them; `testTimeout` is the default of hooks as well as tests; a Babel config whose `babel-jest` doesn't resolve falls back to Oxc with a warning (D68). `fromJestEnvironment(Class, projectConfig)` is the same over a class you hold. `jestEnvironmentFor` is the dialect's `environmentResolver` (a `@jest-environment` docblock, resolved from the project's root as jest-runner does, with `jest-environment-node` and `-jsdom` also found from Jest's own install; `@jest-environment-options` merges over `testEnvironmentOptions`). `jestEnvironmentConditions` is `orchestrator.environmentConditions`: `customExportConditions`, else `['browser']` for the jsdom family, `['node', 'node-addons']`, `['edge', 'edge-light']`, plus `node` always (resolve.exports adds it: `env/conditions-custom`). The node environment of a project stays the built-in `node`; every other `testEnvironment` is the class's absolute path (`NeutralProject.environment.name`). Every environment has one options shape, `{ module?, projectConfig }` (`module` only for the adapter's class; `projectConfig.testEnvironmentOptions` is what the classes and `customExportConditions` read), and `provino jest` maps a name whose options have a `module` to the adapter. ## The vendor directory

- **It's its own `tsc -b` project** (`src/runtime/vendor/tsconfig.json`), with `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` off (DECISIONS D17). Its `outDir` is `.tsc/src/runtime/vendor`, so output paths mirror source paths; otherwise `rewriteRelativeImportExtensions` fails with TS2878. The package's own tsconfig excludes it and references it.
- **Biome skips it** (`!**/vendor` in `biome.json`), so Jest's formatting stays and an upstream diff (T7.15) stays readable.
- **Jest's message packages load on first use (T7.12).** `jest-matcher-utils`, `jest-message-util` and `jest-util` are not imported by the runtime: `vendor/jest-expect/lazy-jest-packages.ts` has a stand-in for each name the matchers import, and each calls the real function, through a synchronous `createRequire` of the same package, the first time a message is printed. Eagerly they cost about 35 ms of cold import (`jest-message-util` 21, `jest-matcher-utils` 14; Chalk, `jest-diff`, Babel's code frame, `graceful-fs`). `this.utils` is a read-through proxy (`lazyUtils`): its keys come in the namespace's (sorted) order, but it is not `Object.isFrozen` (the asymmetric matchers' copy refuses writes instead). `SUGGEST_TO_CONTAIN_EQUAL`, a string, is read through `suggestToContainEqual()`. **`ensureNoExpected`, `ensureNumbers` and `ensureExpectedIsNonNegativeInteger` run on passing assertions** (`toBeDefined`, `toBeTruthy`, `toBeGreaterThan`, `toHaveLength`, `toHaveBeenCalled`, `toHaveReturned`, the `*Times` forms), so each stand-in repeats the condition under which jest-matcher-utils 30.5.2's own function throws and calls the real one, with the same arguments, only then: the message is still the package's, and a worker whose assertions pass never loads it (about 4 ms of the cold start). `lazy-packages.test.ts` holds each condition against the package over a table of values and options, and checks that a file of passing assertions loads none of the three. What they do when they first load stays at boot: `lazy-jest-packages.ts` loads `supports-color` (Chalk's whole colour level: FORCE_COLOR, NO_COLOR and the terminal; Chalk itself stays deferred), `graceful-fs` (it patches `fs.close`, `fs.closeSync`, `process.cwd` and `process.chdir`) and `picocolors` (Babel's code frame) when it is imported, each from the package that depends on it, so a test that sets FORCE_COLOR or spies on `fs` can't change the first failure's colours or have its spy wrapped. `ci-info`, `jest-diff`, the code frame itself, `micromatch` and `jest-util` stay deferred. A new import of one of the three in `src/runtime` must come from the stand-ins; `lazy-packages.test.ts` checks that importing the runtime and building the table loads none of them, and that each stand-in prints what the package prints. Patches are listed in `vendor/UPSTREAM.md` (5).
- **`jestMatchersObject.ts` is Provino's file, not Jest's.** `@provino/expect` owns the slot, so this only reads it, and only when a matcher runs. Loading the vendored modules reads nothing from the slot, which `slot-order.test.ts` checks.
- **`customMatcher.ts` and `messages.ts` are extracts** from Jest's `jestMatchersObject.ts` and `index.ts`, with the line references in the files and in `UPSTREAM.md`.
- **The runtime dependencies are exact pins** at `expect@30.5.2`'s own versions (DECISIONS D18). `jest-mock` is a devDependency, for `types.ts`'s type-only import.
