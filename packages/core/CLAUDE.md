# @provino/core

The test runtime (Track 5): collector, executor, hooks, the test context and the current-test lookup. It runs in the worker, reads only `CorePolicy`, and never imports the loader: the caller passes an `ImportFile` (Track 1 §Module boundaries, rule 6). Every Jest/Vitest difference is a `CorePolicy` value; there is one code path. B07's notes are in `docs/plan/bundles/B07.md`.

## How things fit

- **One store per test attempt.** `runInStore(store)` covers the attempt's each-hooks, body and teardowns; each hook runs in a child store that shares the attempt's `lazy` frame object, so `LazyHost.current()` is the same frame throughout an attempt (guarantee 1). `currentTest.get()` reads the store's `frame` (it carries the hook kind). Suite hooks get a `suite` frame.
- **The per-attempt order** is in `executor.ts`'s header: aroundEach (every level's, outermost first) wraps beforeEach (parent → child) → body → afterEach (child → parent) → the teardowns `beforeEach` returned (once, after *all* levels' afterEach) → `LazyHost` teardowns → `onTestFinished` (last first) → `onTestFailed`. Recorded from the real runners; Track 5's line 81 (teardowns per level) is wrong for `beforeEach`.
- **Two focus algorithms** (`focus.scope`): `file` copies jest-circus 30.5 (describes pass their mode to tests that declare none, unless a describe.only has a direct test.only; `.only` anywhere narrows the whole file); `suite` copies Vitest 5.0's `interpretTaskModes`. The final mode is on the node (`mode`); `TaskNode.mode` keeps the declared one.
- **A skipped suite** never runs its own hooks but still walks its children (so Jest's describe.only inside describe.skip runs). Whether a running suite's `beforeAll`/`afterAll` run is `hooks.skippedBlock`: `run-before-all` is jest-circus's `hasEnabledTest` (a todo counts); `none` is Vitest's suite collapse (an empty suite still runs its hooks).
- **Collection failures** (an import that throws, an async describe under `asyncDescribe: 'throw'`, …) report no tasks and fail the file, as both runners do (`crashed` in a golden).
- **Locations** are captured at registration (3 frames, or 10 under `locationFrame: 'test-file'`) and parsed once when the tree is built, hooks included; off with `locations: false`. `'caller'` takes the first frame (Jest), `'test-file'` the first frame in the test file (Vitest).
- **`.failing`/`.fails`** (`status.expectFail`): `'body'` reverses the body's result in `#runBody`; `'attempt'` reverses the whole attempt after the around chain, and `onTestFailed` runs from the real result before that.
- **`ctx.skip(note?)` / `skip(condition, note?)`** throws a `SkipSignal`; the body, an each-hook and `#callUser` catch it, set `attempt.skipped`, and the attempt ends `skip` (`skipReason: 'dynamic'`, `note`) unless something failed. `afterEach` and `onTestFinished` still run after it; a skip in `beforeEach` stops the chain. Recorded: `runtime/context-skip`.
- **Retries** (T5.10): a test's plan is its own `retry`, else the file's default (`Runtime.setDefaultRetry`, Jest's `jest.retryTimes`: `{ count, delay, immediate, logErrors }`, one value replaced whole by each call, cleared when the file ends). A suite reads the default when it starts running, after its `beforeAll` hooks, and holds it for its own tests (jest-circus reads its globals in `_runTestsForDescribeBlockOnce`): a call from a hook or a test body changes the suites that start after it; `logErrors` is read when a retry happens. `retry.timing: 'immediate'` retries inside `#runTest`'s attempt loop (Vitest); `'deferred'` runs the first attempt, emits `test-attempt-end` with `willRetry`, and parks the test: the suite's `#runChildren` resumes the parked tests after its last child and before its `afterAll` hooks, in the order they failed, one test's retries one after the other, sequentially (a concurrent group's included). The default's `immediate` keeps `retryImmediately` working under a deferred policy, and a test with `repeats` retries at once under it (neither runner combines them). A test that already had errors when it ran (a `beforeAll` failure attached to it under `hooks.beforeAllError: 'attach-to-tests'`) is never retried, deferred or immediate: another attempt meets the same error, and Jest's `handleRetry` skips it (`runtime/retry-before-all-error`). A test is one `test-start` and one `test-end` however long its retries wait; other tests' events fall between. A deferred test's `durationMs` is the sum of its attempts and waits. `delay` waits on the runtime's timers before each retry (Jest: after `test_retry`, Vitest: after the failed attempt). `condition` is asked after each failed attempt but the last, with the error serialized; one that throws ends the retries and fails the test with what it threw. A `g` or `y` RegExp condition is tested through a copy, so its `lastIndex` never carries from one failure or test to the next (Vitest 5.0.5 tests the user's own: the same failure retries once and then not; a declared difference, `runtime/retry-condition-regexp-global`). `retryErrors` keeps the earlier attempts' errors when `retry.keepEarlierErrors` or the file default's `logErrors` says so. Recorded: `runtime/retry-*` (the order, the hooks, when `retryTimes` is read, the wait, Vitest's condition and repeats, the errors Jest logs); `retry-condition-function` shows Vitest 5.0.5 never calling a function condition: `retry.functionCondition` (D7) is `ignore-warn` under the Vitest dialect, which keeps that outcome (every failure retries, the function is not called) and warns once a file with a fix hint (`globalThis.console.warn`, as the fake clock's warnings are, so the worker captures it), and `call` in neutral mode and Jest's (Jest has no `condition`), which asks it. Only a function is affected: a `RegExp` is tested under both.
- **Hook points** (`runtime.onBeforeTryTask` / `onAfterTryTask`, T5.8): called around an attempt in its own store. Before = ahead of the first `beforeEach` (the worker puts the mock cleanup there, T4.10); after = behind the last `afterEach`, the `beforeEach` teardowns and the `LazyHost` teardowns, ahead of `onTestFinished` (the assertion-count check lives there, T7.8). A listener that throws fails the attempt (a failing *before* skips the hooks and body).
- **Error attribution** (T5.11): `runtime.captureProcessErrors(target = process)` is the only place core listens; the worker calls it. Under `fail-owner` an exception goes to the test of the frame it was raised in (`currentTest.get()`): a running attempt gets it in its errors; an ended test gets an `unhandled-error` event with `ownerId` the test; a hook outside a test charges the file. A rejection is held until the owner's body is over (or the file ends) and dropped on `rejectionHandled`; one that arrives between files is charged at once (the worker yields a turn after each file for it). Under `report-run` everything is an `unhandled-error` with `ownerId: null` at once. A file with anything charged late ends `fail`. The consumers apply an event charged to a test as that test's failure (the harness's `summarizeRun`, both reporters). Recorded: `runtime/errors-*`, which run in a child process because `node:test` has handlers of its own.
- **Late registration** is the collector's call: it charges the suite's own file (`collect.lateRegistration`) and the runtime only emits the `unhandled-error` event.

## Testing

- `src/**/*.test.ts`: unit tests, one case per policy value, through `internal/test-support.ts`'s `runScript` (an inline "file" under the neutral policy plus overrides). No real-time waits: timeouts use an injected fake clock (`realTimers`, `now`).
- `src/current/propagation.test.ts`: the 23 propagation cases (Track 5 Spikes B). Cases 20–21 run in a child process (`fixtures/process-listeners.ts`), because `node:test` installs its own process handlers.
- **Ground truth against the real runners** lives in `@provino/harness`: `src/runtime-corpus.test.ts` runs every `fixtures/runtime/` fixture through `createRuntime` under each recorded profile (`src/runtime-corpus/profiles.ts` reads the Jest profile from `@provino/dialect-jest` and holds the vitest-stack / vitest-list values until B14's Vitest dialect replaces them) and compares trace, tests, locations and file status with the golden.
- `test/core.test-d.ts`: the public API, and T6.1's check that `Runtime['lazyHost']` satisfies `LazyHost` (§4 D.23).

## Not built yet (each throws `CORE_NOT_IMPLEMENTED` or is absent)

- `ctx.task.result`: not built (T5.8's remaining part). `ctx.task` is the clone-safe `TestTask`.
- `waitForUnhandledRejections` (Jest's one-turn wait after each test) isn't an option: a rejection is held to the end of the body instead.
- Retries: `entireDescribe` (Jest 30.5's describe-level retry, which reruns a block's hooks and every test; `jest.retryTimes` refuses it by name): T5.10's rest. `Runtime.setDefaultTimeout(ms | undefined)` (B17c, `jest.setTimeout`) replaces the policy's test and hook default for tests and hooks with no timeout of their own (`TestNode.timeoutMs` is `undefined` for them and resolves at run time, as a hook's does), read once when the run starts, after collection (circus copies it at `run_start`: a call in `setupFilesAfterEnv` or at module level counts, one in a hook or test body does not), until the file ends; Core takes the number as given (`undefined` leaves the policy's); Jest's reading (`0` and `NaN` are none, a negative value is a 1 ms deadline, as Jest's fires at once) is the Jest facade's, in `host.setDefaultTimeout`.
- Bail and cancel: T5.12. `describe.shuffle`: T5.13. The overhead gate: T5.14. The definition table: T5.9. Tag filters.
- Messages are neutral, not the dialects' text (timeouts, `.only` on CI, empty describes); the dialects own exact text (B14). The exceptions are Jest's `done` errors and its non-promise-return error: Jest's words in `invoke.ts`, because only Jest's policy reaches them.
- `aroundEach`/`aroundAll` don't take a `limitHooks` slot (Vitest holds one through each phase).
- A bad `describe.each` table under `collect.eachTableError: 'failing-test'` registers one failing test; real Jest fails the whole file. B14 records a fixture and decides (fix, or DIVERGENCES).
- The overhead target (≤ 5 µs per empty test with 3 hooks and ALS, T5.14) isn't met yet: 7.9 µs/test with locations off, 14.7 with them on (`local`, after the B07 cleanup). Stack capture at registration is most of the locations-on cost.
