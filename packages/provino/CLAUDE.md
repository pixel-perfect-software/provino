# provino

The umbrella package (layer 6, composition root). B11 built its first part: `provino/node`'s `run()` and the `provino run` bin. B14c added the dialect commands: `provino jest`, `provino vitest` (refused) and bare `provino`. It names the built-ins nobody else may (`jestDialect`, `@provino/env-node`) and wires config, orchestrator and reporters together; `slices: []` in the manifest, so no source file here may name `Policy` or a slice type (the Biome rule `slice-discipline` fails the lint; reading `project.policy.report` by property access is fine).

## Build and exports (B21e, T1.10)

`pnpm --filter provino build` writes one bundle to `dist/` (`tooling/packaging/CLAUDE.md` → "The umbrella"): every `@provino/*` package inlined, `dependencies` the third-party packages they need (`pnpm hygiene` checks the list), six files from the package in a worker's cold start. `exports`: `.`, `./globals`, `./config`, `./node`, `./reporters`, `./environment`, `./jest` (each `provino-source`, `types`, `import`) and `./package.json`; any other path throws `ERR_PACKAGE_PATH_NOT_EXPORTED`. `bin` is the source for the workspace and `publishConfig.bin` the built `dist/cli.js`. `provino --version`, `--help` and `-h` are answered by the bin before it imports the rest (`src/cli.ts` uses a dynamic import of `internal/cli.ts`; `internal/usage.ts` holds `USAGE`, `internal/version.ts` the version), so they load no Oxc native binding. That import is also where a missing binding surfaces: `internal/native-binding.ts` (`missingBindingMessage`) turns it into one message naming this platform's `@oxc-parser/binding-<platform>`, `@oxc-transform/…` and `@oxc-resolver/…` (those it can't resolve from where the base package is installed), exit 1, no stack; any other error is rethrown. `test/native-binding.test.ts` runs the built bin under `test/block-oxc-bindings.ts` (a `registerHooks` resolve hook that fails the binding packages), and `pnpm smoke:install` deletes them from a real tarball install (T10.3, Provino's half). API reports are `etc/provino*.api.md`. `/plugin` (no package) and `/vitest` (T11.16) wait. `test/exports.test.ts` runs the **built** package (turbo `test` depends on `build` here, `turbo.json`): the subpaths and what they export, the refused paths, the bin, and a real project whose test imports `provino`, with a `registerHooks` recorder (`test/load-recorder.ts`) counting the files a worker loads from `dist` (at most 10; it is 6).

## `run()`

Flow: check `config` and `maxWorkers` → `loadProject(config against cwd, { dialects: [jestDialect], environments: { node: env-node }, ci })` → build the reporters and the bus → `runProject` (pool kind and `maxWorkers` only when given, `cache: false` only when asked (otherwise `runProject` keeps its own default cache in `node_modules/.cache/provino`), `stderr` for the workers' own stderr) → `exitCodeFor(summary, { policy, passWithNoTests, reporterFailures })`.

- **Bad input never rejects.** A `UsageError` (no config path, `maxWorkers` not a whole number of at least 1, an unknown reporter), a `ConfigError` (with its issues and `cause` chain) and `OrchestratorError` `ORCH_BAD_PATTERN` are written to `stderr` as `Provino: <message>` and become `{ exitCode: ExitCode.UsageError (2), summary: null }`. Every other error is a bug and rejects. The pattern is checked by `runProject` before anything starts, so no reporter has said anything.
- **Output.** `default` writes to `stderr` (as Jest does, so stdout can carry the JSON); `normalized-json` writes to `outputFile` (resolved against `cwd`) or `stdout`, with `suite` the root directory's name, `runner` `provino:<dialect name, or neutral>`, `runnerVersion` this package's version, and the policy's `orchestrator.unhandledErrors`, so the file's `success` agrees with the exit code. `reportersFor` registers the built-in `normalized-json` reporter last, whatever order it was named in, so it sees every other reporter's failure before it writes. Two `normalized-json` reporters that both write to stdout, an empty `outputFile`, and an `outputFile` that resolves to a directory are usage errors (exit 2), found before the run starts. A reporter that throws fails the run (exit 1), and `run()` also says so on `stderr`, since only `default` shows reporter errors.
- **Re-entrant.** No `process.exit`, no module-level state: the pool and the cache belong to one call, so calls follow each other or overlap on different projects. A config file is read afresh on every call (`loadConfigFile` busts Node's module cache for it; the files it imports are still cached).
- `ci` defaults to `isCi(process.env)`: `CI` set, and not empty, `0` or `false`, ignoring case and spaces (`CI=FALSE` and `CI=' false '` are not CI). That is the one answer for the run: the project is loaded with it, and the `normalized-json` reporter is given the same value (`env.ci`), so the file never disagrees with `--ci`, the `ci` option or the variable. `signal` aborting ends the run with exit 130.

## `provino jest` (B14c, T11.13, U3)

`runJestCommand`: parse the arguments with the Jest dialect's own parser (`jestNodeDialect.cli`, T11.7) → read the config with `createJestConfigReader({ argv, cwd })` (find from `cwd` or `-c`; no config file means Jest's defaults over `cwd`: an inline `{}`), `resolve` and `toNeutral` → print every diagnostic (the reader's warnings, the parser's refusals and "read but not applied" warnings) → one of four modes → `resolveNeutralProject` per project (`ci` is the global config's) and then:

- **run:** `executeProject` with the pool from the global config (`maxWorkers` as Jest normalized it, `-i` is 1; `--workerThreads` is the threads pool), `-t` from `globalConfig.testNamePattern`, the request's file filters (`selectFiles`, so a filtered run still prunes the results cache against the whole set) and no cache with `--no-cache` or `cache: false`. Several projects (the config's `projects`) run in one pool through `runProjects` (D29, B17d): `executeProject`'s `others` and `root` (the config's `rootDir`); exit codes are those of one project. `--projects` is still refused (no task yet). **`--selectProjects` / `--ignoreProjects`** (D69, `select-projects.ts`) keep or drop projects by `displayName` as `jest-core`'s `getConfigsOfProjectsToRun` does (an unnamed project is never selected and never ignored; `--clearCache` still clears every project), and write Jest's texts (the missing-names warning, `Running one project: x` / `Running N projects:` with a sorted list, or why none runs, without Jest's colours) to stdout, or to stderr under `--json`/`--useStderr`. A selection that leaves no project runs nothing and prints Jest's `No tests found` text (`--passWithNoTests`: its one line); exit is the dialect's `noTests` code, or 0 with `--passWithNoTests`. `projects.test.ts` runs each case under live Jest 30.5.2: statuses, stdout and exit code.
- **`-u` / `--updateSnapshot` and `--ci`** (B17b, T7.9): `-u` is the request's `update`, which `executeProject` hands to `runProject` (snapshots that differ are rewritten and obsolete ones removed); `--ci` (or the `CI` variable, as Jest reads it) is the project's `ci`, so a CI run writes no snapshot and fails a missing one. `resolveUpdateMode` in `@provino/snapshot/node` turns the two into Jest's `all`, `new` or `none`. `test/jest-snapshots.test.ts` runs the bin against the `snapshot/*` goldens recorded from Jest 30.5.2 (`update-all`, `new-ci`, `obsolete-ci`): exit code and `.snap` bytes.
- **`--listTests`:** every project's discovered files, filtered, once each and sorted, one path per line, or a JSON array with `--json` (written to `--outputFile` when given, as Jest does). It starts no worker. A project's own `testEnvironment` (jsdom, `jest-fixed-jsdom`, a custom class) runs through the Jest adapter (`JEST_ENVIRONMENT` in `built-ins.ts`, D44): `environmentsFor` maps its absolute path to the adapter, and `jest-environment-node` stays the built-in `node`.
- **`--showConfig`:** `{ globalConfig, configs, version }` as JSON (keys as our reader normalized them; Jest's own output is not compared).
- **`--clearCache`:** removes each project's Provino cache directory (`node_modules/.cache/provino`, or `<cacheDirectory>/provino` when the Jest config sets `cacheDirectory` itself, D70; the transform cache `t/` goes with it) and prints `Cleared <dir>` once per directory (projects share one). A directory is removed only when it holds a Provino marker (`CACHEDIR.TAG` with Provino's signature, `results.json` or `t/lockfile-hash`, `isProvinoCacheDir`); a user's own `<cacheDirectory>/provino` is left with a notice on stderr. It leaves the rest of a shared `cacheDirectory` (Jest's own haste map) alone, where Jest's `--clearCache` removes the whole directory. `test/cache-directory.test.ts` covers both locations.

**Exit codes are Jest's.** A command line or config Jest refuses (a `JestCliError` or `JestConfigError`, a refused flag, a pattern that isn't a regular expression) prints Jest's text, or `Provino: <message>`, to stderr and exits with the Jest dialect's `orchestrator.exitCodes.usage` (1; the neutral value, and every non-Jest command, is 2). A failed test is `testFailureExitCode` (1), no tests found is `noTests` (1) unless `--passWithNoTests`. `test/jest-exit-codes.test.ts` runs the bin against black-box `run` goldens recorded from Jest 30.5.2.

**Bare `provino [--dialect jest|vitest] [args]`** (`detect.ts`): `--dialect` skips the search. Else a `provino.config.{ts,mts,cts,js,mjs,cjs}` in `cwd` runs as `provino run --config <it> <args>`; else the Jest config found from `cwd` (the upward walk Jest does; a `package.json` counts only with a `jest` key) or a `vitest.config.*`/`vitest.workspace.*` in `cwd` decides; both is an error naming `--dialect`; none is an error. A Vitest project is refused until T11.15/T11.16 (a `vite.config.*` with a `test` key isn't detected: it needs Vite). `provino vitest` is refused the same way. No `jest` or `vitest` bin is published (`dispatch.test.ts` reads every package's `bin`).

## The bin

`provino run --config <file> [--maxWorkers n] [--pool forks|threads|inline] [--reporter name]… [--outputFile path] [-t pattern] [-u] [--ci] [--passWithNoTests] [--no-cache]`. A missing command, an unknown command or flag, a missing `--config`, a bad value, or `--outputFile` without `--reporter normalized-json` prints the message and the usage text to stderr, exit 2. `--help` prints the usage text to stdout, exit 0. A bug prints its stack, exit 1. The bin sets `process.exitCode` and never calls `process.exit`. With forks or threads the pool has stopped every worker, so the process ends on its own (`test/cli.test.ts` runs it with a deadline). **With `--pool inline` it may not:** the worker shares the process, so a test's leaked handle (timer, socket) keeps it alive, as with Jest's `--runInBand`; `--forceExit` is T9.10.

- `-u` / `--updateSnapshot` (`RunOptions.updateSnapshot`, B17b) rewrites the snapshots that differ and removes the obsolete; without it new snapshots are written, and none in a CI run (the `snapshot` policy, resolved by `runProject`).
- `-<short>=<v>` is rewritten to the long option before `parseArgs` (which would keep the `=` in the value), for every string option with a short name in the options table (today `-t` and `-c`). A repeated `--reporter` name is a usage error.
- An inline pool runs one worker (the orchestrator caps it). An inline worker doesn't capture console, so a test's `console.log` reaches stdout: use `--outputFile` for normalized-json with `--pool inline`. With forks or threads, the workers' own stdout goes to stderr.

  - `jest-dom.test.ts`, `jest-environments.test.ts`, `jest-facade.test.ts`, `jest-object.test.ts`, `jest-resolve.test.ts`, `env-docblock-none.test.ts` (B17c): per-test statuses against real Jest 30.5.2 (the recorded goldens, and for the DOM projects and the five environment packages a live Jest run on the same tree, `test/live-jest.ts`), through `runJestCommand`'s `reporters` hook (as `normalized-json`; `provino jest` has no flag for it, T11.9). Declared divergences are named in each file.
  - `jest-mock-cleanup.test.ts` (T4.10, B17a): the project's `clearMocks`, `resetMocks` and `restoreMocks` reach the worker's mock cleanup through `provino jest` (each key against a control without it, and no "not applied" warning for them).
- `test/*.test.ts`: real projects generated into `$TMPDIR` as text (no `.js` is committed, D13): a Jest-style `tests/*.test.js`, a `provino.config.mjs` and a CommonJS `package.json` (`test/support.ts`: `makeProject`, `trackedProjects`, `spawnCli` with a deadline, `viewOfNormalized`). Real forks by default.
  - `run.test.ts`: `run()` (pass, fail, the exit-2 cases, no files, `-t`, both reporters, `env.ci` in the JSON, the cache, the pools, `maxWorkers`, sequential and concurrent calls, an aborted signal).
  - `cli.test.ts`: the bin as a child process.
  - `crash.test.ts`: B11's acceptance check: a test that sends its worker SIGSEGV fails that file (`workerExit` `{ type: 'signal', signal: 'SIGSEGV' }`, `FAIL` with "killed by SIGSEGV", `crashed` in the JSON), the other files pass, no worker outlives the run; through `run()` and through the bin. Skipped on win32.
  - `runtime.test.ts` (B17a): fake timers and the errors a test leaves behind, through `run()` on forks: a callback fires as the test that scheduled it (`expect.getState().currentTestName`, whoever calls `jest.advanceTimersByTime`), the real timers are back for the next file, Jest's not-faked warning, a late timer's exception fails the test that made it, and so does a rejection nobody handled.
  - `run.test-d.ts`: the types of `run`'s options and result.
- Test files note their worker's pid in a file under the project (`noting`) so a test can check afterwards that every worker has exited.
- Workers' own stderr goes to the `stderr` you pass. Some environments (this sandbox) print noise there at every Node start, so assert with patterns, not that stderr is empty.
